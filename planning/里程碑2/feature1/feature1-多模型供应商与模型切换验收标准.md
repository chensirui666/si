## 提供方配置

<a id="case-01"></a>

### 01 添加界面只列还未配置的提供方

- **类型**　组件测试（Chromium）。
- **目的**　验证已配置列表与添加选项来自同一份服务端状态。
- **怎么测**　用构造数据配置 DeepSeek，把 Moonshot 标为未配置。打开「设置 → 模型」，再点「添加提供方」。检查模型页列出 DeepSeek，添加界面可选 Moonshot，DeepSeek 不出现在添加选项中。

<a id="case-02"></a>

### 02 保存第二家提供方后两家的模型立即可选

- **类型**　实际网页入口 E2E（受控服务商）。
- **目的**　验证配置保存到候选列表刷新的完整链路。
- **怎么测**　先配置 DeepSeek，再通过网页添加 Moonshot 并填入格式有效的构造 Key。检查设置页显示两家已配置，聊天候选按提供方分组显示两家的模型。添加列表移除 Moonshot。受控模型服务收到的远端请求数为零，HTTP 响应及网页内容均不包含明文 Key。

<a id="case-03"></a>

### 03 编辑已有提供方后实际请求使用新 Key

- **类型**　服务集成测试（受控服务商）。
- **目的**　验证替换凭据及后续读取规则。
- **怎么测**　先保存一个构造 Key，再通过编辑接口换成另一个。用该提供方发起任务，检查受控服务商只收到新 Key，另一家原有凭据和可选模型保持正确。

<a id="case-04"></a>

### 04 删除提供方后聊天候选移除该组模型

- **类型**　实际网页入口 E2E（受控服务商）。
- **目的**　验证凭据删除、候选更新和不可用选择的处理。
- **怎么测**　在已有会话选 DeepSeek 并配置好另一家。删除 DeepSeek Key。检查候选只剩仍有 Key 的提供方，添加列表再次提供 DeepSeek。已有会话提示重新选择，选定新模型后方可发送。

<a id="case-05"></a>

### 05 本机凭据保存失败时保留表单并提示

- **类型**　实际网页入口 E2E（受控本机写入）。
- **目的**　验证保存错误反馈与原配置保护。
- **怎么测**　预先配置 DeepSeek，再让凭据文件的下一次写入明确失败。通过设置添加 Moonshot。检查表单保留输入并显示脱敏错误，设置页和聊天候选维持已确认状态，DeepSeek 的原凭据可读取。

<a id="case-06"></a>

### 06 另一已打开页面同步提供方配置

- **类型**　服务集成测试（两个 WebSocket 客户端）。
- **目的**　验证配置变更通知覆盖多个页面。
- **怎么测**　用两个已授权连接订阅会话。第一个客户端保存第二家 Key。检查第二个收到模型变更通知，重新查询时取得两家模型。该通知沿用独立于会话更新的序列。

<a id="case-07"></a>

### 07 格式有效但被提供方拒绝的 Key 在实际发送时报告

- **类型**　真实 API 集成测试（按型号执行）。
- **目的**　验证保存只做本地检查，真实认证失败有对应任务终态。
- **怎么测**　在隔离配置中保存一个格式有效、已知无效的测试 Key。确认模型仍可选。主动发送一条测试消息，核对该提供方的实际认证拒绝、网页红字以及任务失败状态。检查没有工具执行，错误或记录未泄露密钥。

## 模型与推理强度

<a id="case-08"></a>

### 08 切换模型时使用目标模型的档位与默认值

- **类型**　组件测试（Chromium）。
- **目的**　验证菜单和当前选择随模型能力变化。
- **怎么测**　使用构造目录，模型 A 支持 Low、High，模型 B 支持 Medium、High 且默认 Medium。在 A 选 High，切到 B。检查输入框显示 B 和 Medium，菜单只提供 B 的档位。

<a id="case-09"></a>

### 09 模型无可调档位时省略推理强度入口

- **类型**　组件测试（Chromium）。
- **目的**　验证没有档位的模型可正常选择。
- **怎么测**　配置一个无可调推理档位的构造模型并选择它。检查菜单显示模型选择项，保存请求中省略推理档位，页面确认后可发送。

<a id="case-10"></a>

### 10 已建立会话改档位后退出，重开恢复本会话和新默认

- **类型**　实际网页入口 E2E（受控服务商）。
- **目的**　验证最后选择早于下一条消息持久化。
- **怎么测**　准备已分别保存选择的会话 A 和 B。在 A 选新模型和档位，收到确认后直接关页并重启服务。检查 A 恢复新选择，B 恢复其原选择，新建草稿继承 A 更新的默认值，期间没有模型请求。

<a id="case-11"></a>

### 11 新建草稿的选择成为默认并随首条消息进入会话

- **类型**　实际网页入口 E2E（受控服务商）。
- **目的**　验证新建草稿与已保存会话的交接。
- **怎么测**　在新建草稿选模型和档位。收到确认后检查新建会话默认值已更新，侧栏还没有这段会话。发送首条消息后检查会话登记、原文和初始选择都已保存，重开时可恢复。

<a id="case-12"></a>

### 12 选择保存回滚时两处继续使用原值

- **类型**　存储与服务集成测试。
- **目的**　验证会话选择与默认值一起提交。
- **怎么测**　先保存会话 A 的旧选择及默认值。注入一次可确认的事务失败，再请求修改 A 的档位。检查接口返回失败，重新查询会话与新会话默认值都仍为旧值。

<a id="case-13"></a>

### 13 运行中可预选模型，当前任务结束后才可发送

- **类型**　实际网页入口 E2E（受控服务商）。
- **目的**　验证运行中可以保存下一次的选择，当前任务继续使用原设置，新消息须等当前任务结束。
- **怎么测**　用 A 发起任务，在受控服务商返回工具调用前暂停。通过同一会话的菜单选择 B 并调档，确认会话的下次选择和新会话默认值都已保存，输入框显示 B，当前任务仍显示 A。输入草稿并按 Enter，检查网页保留草稿且未发送。通过测试客户端直接向该会话提交新消息，检查服务端返回会话忙碌。恢复 A 的运行，让工具结果回填后触发自动压缩。检查摘要请求和下一次模型请求仍使用 A 的原档位。A 结束后主动发送草稿，检查新任务实际使用 B 和新档位。

<a id="case-14"></a>

### 14 同一会话在另一页面改选后自动同步模型和档位

- **类型**　实际网页入口 E2E（受控服务商）。
- **目的**　验证同一会话的多个页面自动同步下次使用的模型和档位。
- **怎么测**　在两个页面打开同一空闲会话，第二个页面留一段草稿。第一个页面把模型从 A 换成 B 并调档。检查第二个页面在收到会话更新后自动显示 B 和新档位，草稿保留。直接发送，核对服务商收到 B 和新档位对应的请求。

<a id="case-15"></a>

### 15 发送早于模型同步时保留草稿并刷新选择

- **类型**　实际网页入口 E2E（受控服务商与延迟通知）。
- **目的**　验证用户看见的模型设置与实际请求一致，自动同步后可以继续发送。
- **怎么测**　在两个页面打开同一空闲会话。第一个页面保存 B，延迟送往第二个页面的选择变更通知。在第二个页面仍显示 A 时按发送，检查服务端返回模型设置已更新，本次消息未接收，模型调用数为零。检查该页面自动取得最新快照，显示 B 和新档位，恢复草稿并提示「模型设置已更新，请确认后再发送。」再次主动发送，核对仅有一次模型请求，实际使用 B。

<a id="case-16"></a>

### 16 旧会话从已有任务记录恢复 DeepSeek 选择

- **类型**　存储与服务集成测试。
- **目的**　验证历史库升级后的兼容。
- **怎么测**　使用仅有旧任务记录、没有模型选择表数据的构造会话库。加载一段已用 DeepSeek Flash 的会话，确认历史和工具记录可读，网页恢复 DeepSeek Flash 与原有 High。

## 实际执行与跨模型续做

<a id="case-17"></a>

### 17 真实模型流式调用工具并在同一任务多轮续做

- **类型**　真实 API 集成测试（按型号执行）。
- **目的**　验证单个型号能进入项目现有的编程任务循环。
- **怎么测**　在隔离的测试工作区放置构造的线索文件。发任务让模型先读线索，再读其中指定的第二个文件，并按已读内容给出可核对的结果。核对至少两轮工具与模型请求、每个调用编号与结果、最终回答和模型身份。模型有档位时检查实际请求使用所选档位。核对网页的思考与用量来自实际响应。

<a id="case-18"></a>

### 18 真实模型运行中中止后结束本轮

- **类型**　真实 API 集成测试（按型号执行）。
- **目的**　验证中止传到提供方调用，当前会话可以继续。
- **怎么测**　用该型号发起任务，在受测模型已开始流式输出且尚未结束时点击中止。核对服务端进入已中止状态、后续调用停止，先前已保存的内容和工具结果可回看。确认终态后可在原会话提交下一条消息。

<a id="case-19"></a>

### 19 真实手动压缩后用当前模型继续工作

- **类型**　真实 API 集成测试（按型号执行）。
- **目的**　验证真实摘要写入及后续请求使用有效上下文。
- **怎么测**　在隔离会话中准备包含构造事实与工具结果的可压缩历史，选定受测型号后发送 /compact。检查摘要请求实际发给该型号、摘要有内容且生效，原始消息仍可看。再发一条依赖摘要中事实的任务，核对模型使用摘要和近期原文继续。

<a id="case-20"></a>

### 20 在真实会话里跨提供方续做并切回

- **类型**　真实 API E2E。
- **目的**　验证真实历史能跨协议交接。
- **怎么测**　用 DeepSeek 在测试工作区读取文件并完成一部分任务。换一家协议不同的模型继续，检查工具实际执行及结果配对。再切回 DeepSeek，发一条仍需工具的消息。检查三个阶段都在同一会话，历史可回看，目标 API 接受整理后的输入并有可核对的实际结果。

<a id="case-21"></a>

### 21 目标模型拒绝旧历史时展示实际失败原因

- **类型**　服务集成测试（受控服务商）。
- **目的**　验证历史兼容失败的收尾与恢复边界。
- **怎么测**　用 A 保存带工具结果的历史，切到 B 并发送。让 B 的受控接口拒绝历史格式。检查本轮以实际失败终态结束，红字提示对应问题，历史与已发生的工具结果完整，后续模型请求停止。

<a id="case-22"></a>

### 22 服务商没有提供用量时，页面不显示虚构的零用量

- **类型**　模型适配集成测试（受控服务商）。
- **目的**　验证 SDK 初始化值与真实用量的边界。
- **怎么测**　用受控提供方发送一个有文本、无用量字段的成功响应。检查项目事件与会话记录省略未知用量，网页没有显示实际用量为零，容量提示仍可显示近似估算。

## 容量与压缩恢复

<a id="case-23"></a>

### 23 切到容量较小的模型时用该模型自动压缩

- **类型**　会话集成测试（受控模型）。
- **目的**　验证当前选择同时决定摘要与正常请求的去向。
- **怎么测**　构造一段 A 的历史，令 B 的容量接近阈值，且摘要请求能装下。切到 B 发送。检查摘要和正常请求都使用 B，摘要后有效历史装得下，原始聊天仍可回看。

<a id="case-24"></a>

### 24 摘要请求本身超限时本轮显示通用红字

- **类型**　实际网页入口 E2E（受控模型）。
- **目的**　验证发送前容量失败的真实终态与用户引导。
- **怎么测**　为 B 配置较小的构造容量，使摘要请求也装不下。切到 B 后发送，检查 B 的摘要和正常生成调用都未发出。该轮失败，在回复位置显示「当前模型容量不足，无法继续这轮，请切换模型重新压缩。」会话历史可回看。

<a id="case-25"></a>

### 25 摘要生成后历史仍超限时本轮显示同一句红字

- **类型**　会话集成测试（受控模型）。
- **目的**　验证已有摘要结果不足时的容量保护。
- **怎么测**　令 B 能接收摘要请求，但让返回的摘要和保留内容仍超出 B 的正常输入预算。检查本轮以失败结束，错误文案与案例 24 一致，压缩记录说明原因，之前的有效上下文仍可使用。

<a id="case-26"></a>

### 26 容量不足后换模型手动压缩再切回，可以继续

- **类型**　实际网页入口 E2E（受控模型）。
- **目的**　验证用户能在原会话完成恢复闭环。
- **怎么测**　从 B 容量失败的会话开始，切换到能处理原历史的 A，在同一会话发送 /compact。构造摘要使剩余上下文能装入 B。再切回 B 并主动发送，检查 B 使用新摘要继续，A 和 B 的旧记录都可回看。

<a id="case-27"></a>

### 27 提供方明确报告超限时恢复一次，已完成工具只执行一次

- **类型**　会话集成测试（受控模型）。
- **目的**　验证复用已有的超限恢复与工具结果保护。
- **怎么测**　先让 B 成功调用本地工具并写入结果，再让下一次请求返回明确的容量超限。检查只为同一失败输入尝试一次压缩与继续，压缩由 B 执行，已完成工具的执行计数保持为一。

## 执行说明

- **现有覆盖**　复用 [WebServer 模型配置测试](../../../packages/server/test/webserver.test.ts#L264)、[会话存储验收](../../里程碑1/feature10/feature10-验收标准.md)、[模型流测试](../../../packages/model/test/model-stream.test.ts)和 [DeepSeek 真实网页测试](../../../web/tests/e2e/deepseek-live.spec.ts)。在各层扩展现有用例，使用仓库的 [校验命令](../../../docs/development.md#校验)。
- **受控测试**　使用独立临时会话库、临时凭据文件、测试工作区与受控流。重点核对错误分支、写入状态、模型请求与工具调用计数。网页实际入口用于跨页面、重开服务、红字与恢复交互。
- **真实 API**　从已授权网页或实际 HTTP 与 WebSocket 入口发起请求，使用测试凭据与测试工作区。记录提供方、实际入口、请求模型、推理档位、依赖版本、工具结果、最终状态和可核对的效果。证据中的密钥和认证头须脱敏。缺少凭据或未执行的型号标为「待验证」。
- **发布口径**　已接通的 Pi 目录型号可以选用。验收记录按型号写明各真实用例的完成状态。某个型号通过，结论只覆盖该型号与所测入口。
