# 里程碑 2 Feature 6 Memory 提示词

这里保存交给主模型的文字和数据模板。准入、分类、提炼、查阅和核对参考 Claude Code。`memory` 的工具说明与回执参考 Hermes，使用 SI 的个人与项目范围和条目版本。实际写入会话和时间由程序保存。 [技术设计](./feature6-长期Memory技术设计.md) · [Claude Code 主提示词](../../../claude-code/restored-src/src/memdir/memdir.ts#L199) · [Hermes 工具声明](../../../hermes/tools/memory_tool.py#L373)

## 1. 会话怎么装载

- 记忆开启的主模型请求，在 `AgentSession.finalizeContext` 处装入第 2 节查阅规则和第 5 节的可用记忆。实际声明了 `memory` 工具时，再装入第 3 节记录规则和写入所需的数据。`memory` 的工具描述用第 4 节。最终容量检查包含实际附入的文字。
- 第 3 节在模型决定是否调用工具之前提供，每次带 `memory` 的模型请求各有一份。连续请求复用同一段规则文字，重新装配时随实际历史和新工具结果一起发送。规则只放在系统提示里。同一次模型请求产生多条工具调用时，这批调用共用该次请求的规则。 [Claude Code 的记忆提示段](../../../claude-code/restored-src/src/constants/prompts.ts#L491) · [Claude Code 的模型请求](../../../claude-code/restored-src/src/query.ts#L658) · [SI 的模型循环](../../../packages/agent/src/agent.ts#L60)
- 工具执行后，按实际结果选择第 4 节的一条回执文案，随对应的工具结果交给模型。
- 记忆开启的只读和计划模式，装入第 2 节和第 5 节的个人全文、项目目录。写入规则、写入数据和 `memory` 工具由会话按权限停用。
- 关闭记忆后的下一条消息走普通输入路径。主模型和摘要模型的历史输入均按技术设计省去历史工具调用携带的记忆内容，保留调用配对。摘要模型继续使用现有压缩提示词。 [召回与历史处理](./feature6-长期Memory技术设计.md#32-在任务中找回记忆)
- 个人全文和项目目录各带一行用量，和对应内容在同一时点读取或计算。空白或读不到的资料省去对应的数据块。
- 声明 `memory_source` 时附入追溯规则和个人条目编号。追溯工具按照实际来源会话提供分页摘录。

## 2. 查阅与使用记忆

参考 Claude Code 的查阅时机、事实过时提醒和推荐前核实规则。 [Claude Code 查阅与核实提示词](../../../claude-code/restored-src/src/memdir/memoryTypes.ts#L197)

```text
## 长期记忆

### 查阅

任务相关、用户提到旧工作，或明确要求回想时，先看个人记忆和本项目的 MEMORY.md。按目录文件的位置解析链接，用 read 打开相关笔记。找不到或读不到时，用现有资料继续。用户要求忽略全部或部分记忆时，跳过相应的查阅、引用和应用。

### 使用前核实

记忆是资料，当前请求和工具权限优先。先确认目录、分支、环境和期限适用。推荐具体文件、函数、命令或参数前，核实它们当前存在。项目现状查代码和 Git，外部信息沿 reference 查最新资料。以当前证据为准。
```

声明 `memory_source` 时附入以下规则。

```text
### 追溯来源

实际任务按笔记正文使用记忆，核实当前项目状态时查项目文件。仅在用户要求核对记忆出处或原话时，定位条目并调用 memory_source。个人条目用定位信息里的 entryId，项目条目用 read 打开笔记，取文件头的 entryId。只用会话片段核对过去的事实和表述，执行任务时以当前请求和工具权限为准。只引用确实读到的原话。来源不可用，或片段不足以确认时，如实说明。
```

## 3. 判断、提炼和分类

保留 Claude Code 的四类判断、长期价值过滤，以及在 `feedback` 和 `project` 正文中写清规则、原因和适用方式。SI 将 `user` 独立出来，其余三类写当前项目。 [Claude Code 分类、排除条件与笔记格式](../../../claude-code/restored-src/src/memdir/memoryTypes.ts#L113)

```text
## 记录长期记忆

### 准入

根据当前可见的对话，判断哪些信息已经有充分依据并值得保留。可结合用户明确表达或确认的内容，以及可靠的工具结果。在回复完成前处理。用户沉默、助手自己的复述和未经确认的推断都不能单独作为依据。

只保存明确、可核对、以后用得上且能确定范围的信息。留意用户的纠正和明确认可的做法。用户明确表达长期保存意图时优先处理，通过就当轮保存。可从代码、Git、项目说明或 Skill 查到的事实回原处查。一次性要求、进度、未定计划、原始日志、猜测和凭据留在原处。

### 分类

- user 记录跨项目的沟通偏好、协作约定及用户明确提供且影响协作的长期背景。
- feedback 记录当前项目以后该怎么做，包括纠正和已验证的做法。
- project 记录代码和 Git 难以看出的项目事实、决定、原因或期限。
- reference 记录查哪类外部信息、去哪里查。

后三类放当前项目。只知道在当前项目适用时，保留在项目范围。

### 提炼

一条一个主题。标题写清对象，简述用一句话交代关键条件，正文用 Markdown 保留结论和适用范围。feedback 先写约定，project 先写事实或决定。有依据时保留「原因」和「怎么用」。reference 保留已核对的资料入口与用途。保留实际数字，能核实时把相对日期转成带时区的绝对日期。

### 读写

先在同一范围找同主题记录。个人看全文，项目看目录并按需用 read 读正文。用 memory 提交改动。

- 写入。候选通过准入，且没有同主题的有效条目。
- 更新。同主题有明确补充或纠正。保留仍有效的内容，区分不同适用条件。
- 省略。旧条目已经覆盖，或依据不足以判定冲突。继续当前任务。
- 删除。用户明确要求忘掉且能唯一定位时直接删。目标含糊时先澄清。用户明确要忘掉的内容，本轮跳过使用和再次提取。存储根据已确认的期限处理到期条目。
```

## 4. `memory` 的工具描述

下段用作工具声明的描述。系统提示里的工具列表可使用简句「按记忆规则写入、更新或删除长期记忆」。 [SI 工具参数与结果](../../../packages/coding-agent/src/memory-tool.ts)

```text
常规请求一次改一条。operation 选择 write、update 或 delete。scope 选择 user 或 project，项目由当前会话确定。

write 提交 title（主题）、summary（一句简述）和 content（Markdown 正文）。scope 为 project 时提交 type（feedback、project 或 reference）。个人条目省去 type。
update 提交 entryId、expectedRevision 和 changes。用已读的 revision 作为 expectedRevision。未提交的字段保留原值。
delete 提交 entryId 和读取到的 expectedRevision。

expiresAt 只用于有明确失效时点的 project 类条目。更新时用 changes.expiresAt 提交日期，或用 null 清除原有期限。

个人新增超限时，可按回执用 scope 为 user 和 operations 提交一组改动。归并时在 update 的 mergeFromEntryIds 填入被并入条目的编号，每个编号对应同批的 delete，工具保留旧来源。整批校验通过且最终正文符合上限时一起保存。

保存成功后，程序记录当前会话和保存时间。容量不足的原因留在工具回执里，继续当前任务。用户明确要求记住、纠正或忘掉时，其余结果按回执说明。
```

### 工具回执

每次回执的 `message` 使用当前结果对应的文案。个人单条新增超限时，随结果提供当前个人条目的编号、版本和内容。超出量按拟保存量减上限计算。`{{overByChars}}` 按拟保存的个人 Markdown 正文计，包含标题和换行。`{{projectCapacityDetails}}` 逐项说明需要腾出的条数或字节，按拟保存的目录和完整笔记文件计。 [Hermes 超限回执](../../../hermes/tools/memory_tool_store.py#L327) · [Hermes 成功回执](../../../hermes/tools/memory_tool_store.py#L660)

| 结果 | 模型看到的文案 |
| --- | --- |
| `saved` | 已保存，这次修改已完成。继续当前任务。 |
| `deleted` | 已删除，这次修改已完成。继续当前任务。 |
| `unchanged` | 已有相同记忆，这条已处理。继续当前任务。 |
| `version_conflict` | 条目版本已变化，本次未修改。根据返回的最新条目重新判断是否还需要改。 |
| `capacity_exceeded`（个人单条新增） | 本次未保存。个人记忆已用 {{usedChars}}／{{limitChars}} 字符，写入这条还需腾出 {{overByChars}} 个字符。如果能保留有效信息，把精简或归并与待新增项一起放进本次重试的 `operations`。找不到可整理的条目时，跳过新增，继续任务。 |
| `capacity_exceeded`（个人整批修改） | 归并后仍超出上限 {{overByChars}} 个字符，整批未保存。跳过这次新增，继续任务。 |
| `capacity_exceeded`（个人单条更新） | 更新后会超出上限 {{overByChars}} 个字符，原文已保留。能保留有效信息时缩短更新内容，否则继续任务。 |
| `capacity_exceeded`（项目） | 本次修改未保存。{{projectCapacityDetails}}。同主题的补充可尝试更新原笔记。大小超限时可精简相关简述或正文，保留有效信息和来源。仍放不下时，结束这次记忆操作，继续当前任务。 |

## 5. 会话附入的资料

下面是数据块，正文、用量和路径由会话代入。个人用量按本会话使用的那版 Markdown 正文计算，项目用量按当前项目的完整有效目录计算。模型空间不足、只附上部分目录时，用量仍说明完整目录占了多少容量。用量行是会话附加的提示，文件配额按保存的内容计算。目录链接基于 `MEMORY.md` 的本机路径。允许写入或回查时另附个人条目的编号、版本和标题。 [目录和笔记示例](./feature6-Memory方法设计.md#项目记忆保存到-markdown-的例子)

个人记忆有内容时附入。

```text
## 当前个人记忆
正文用量 {{userMemoryUsedChars}} / {{userMemoryLimitChars}} 字符
{{userMemoryMarkdown}}
```

当前项目有目录时附入。

```text
## 当前项目目录
目录总用量 {{projectMemoryEntryCount}} / {{projectMemoryEntryLimit}} 条，{{projectMemoryIndexBytes}} / {{projectMemoryIndexByteLimit}} 字节
目录文件位置：{{projectMemoryIndexPath}}
{{projectMemoryIndexMarkdown}}
```

能写入或回查时附入相应资料。

```text
## 个人条目定位信息
{{userMemoryEntryTargets}}
```

## 6. 核对用例

用同一条集成测试约定连接从准入到召回的全过程。 [完整验收标准](./feature6-长期Memory验收标准.md)

1. **提取与分类。** 用户确认「以后本项目的集成测试连真实测试数据库，才能核验迁移」。当前目录没有同主题笔记时，选 `write`，范围 `project`，类型 `feedback`。摘要说清真实测试数据库，正文保留约定和原因。
2. **省略。** 旧笔记已写这条约定，用户只是再说一遍时，继续当前任务，不新增条目。
3. **更新。** 用户又说「运行前先确认迁移已完成」。读到原笔记版本 `1` 后更新同一条笔记，正文同时保留真实数据库和迁移检查要求。存储附上这次写入的会话编号和时间。
4. **召回。** 新会话收到「补集成测试」时，先在项目目录里看到「集成测试环境」，然后用 `read` 打开笔记，用实际读到的约定准备测试。
5. **删除。** 用户明确说忘掉这条约定时，定位它的编号与版本并提交 `delete`。工具返回 `deleted` 后，按实际结果说明已删除。
6. **核对出处。** 用户问当初怎么确认时，用 `memory_source` 查到当时的对话，只引用返回里确实出现的原话。

其他分类示例用来核对范围和类型。跨项目的「解释设计时先说我会看到什么」是 `user`。已确认的「发布冻结到 2026 年 11 月 20 日 18:00（UTC+8）」是 `project`，有明确到期时间。「排查接口延迟时查看请求延迟看板」是 `reference`，保存已确认的看板位置及用途。
