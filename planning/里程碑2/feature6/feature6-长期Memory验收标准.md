## 写入与写入限制

<a id="case-01"></a>

### 01 默认开启时保存项目约定并记录写入出处

- **类型** 集成测试（受控模型）。
- **目的** 证明首次使用时会话能让主模型保存一条项目记忆。
- **怎么测** 使用未配置记忆的临时本机设置和新仓库。模型提出长期测试约定后，用户在下一轮确认。受控模型直接提交提炼后的 `feedback`，核对 `memory` 调用结果、主题文件及服务端记录的真实会话编号和写入时间。

<a id="case-02"></a>

### 02 相同内容重复提交时保留已有笔记

- **类型** 集成测试（受控模型）。
- **目的** 避免重复新增落盘。
- **怎么测** 先有一条「集成测试使用真实测试数据库」。本轮再次提交完全相同的范围、正文和适用条件。核对返回 `unchanged`，回执提示这条已处理，笔记数、版本和文件内容维持原值。模型直接省略候选也会结束判断。

<a id="case-03"></a>

### 03 明确补充时更新同一条笔记

- **类型** 集成测试（受控模型）。
- **目的** 证明更新写回原条目并保留适用内容。
- **怎么测** 让模型读版本 1 的「集成测试环境」，用户补充「运行前先确认迁移已完成」。提交更新后核对同一个编号变为版本 2。正文同时包含真实数据库约定与确认迁移的要求，出处包含支持该版本的消息。

<a id="case-04"></a>

### 04 另一会话先保存后拒绝旧版本更新

- **类型** 集成测试。
- **目的** 验证并发修改不会互相覆盖。
- **怎么测** 两个会话读到同一条项目笔记的版本 1。先由 A 更新成版本 2，再由 B 按版本 1 提交修改。核对 B 收到 `version_conflict` 和当前条目，原文件仍为 A 保存的版本。

<a id="case-05"></a>

### 05 只读会话不能调用记忆写入

- **类型** 集成测试（受控模型）。
- **目的** 保证只读模式停用写入工具。
- **怎么测** 以只读模式提交一个值得记的约定。检查模型仍有召回资料和 `read`，写入规则、来源数据和 `memory` 工具均省去。模拟模型仍请求写入时核对失败结果按原编号回填，磁盘记忆保持原样。

<a id="case-06"></a>

### 06 计划模式不能调用记忆写入

- **类型** 集成测试（受控模型）。
- **目的** 保证计划模式停用写入工具。
- **怎么测** 开一个计划模式会话并给出项目偏好。检查声明的工具，模拟一条 `memory` 调用。确认模型能继续规划，记忆库没有发生写入。

<a id="case-07"></a>

### 07 保存提交前停止任务时保留原文件

- **类型** 集成测试（受控模型）。
- **目的** 验证取消路径不会留下半条记忆。
- **怎么测** 在准备一次更新时，在存储提交前触发停止。比对操作前后笔记内容和版本，检查任务结束为停止。已保存的记忆文件保持原样。

<a id="case-08"></a>

### 08 个人记忆空间不足时保留原文

- **类型** 单元测试。
- **目的** 验证上限同时约束新写入和状态回执。
- **怎么测** 按技术设计建议上限准备一份已接近 1,375 字符的个人文档，再提交会超限的新增。核对 `capacity_exceeded`、用量、上限和当前条目的编号、版本及内容。回执中的超出量应等于拟保存的完整正文字符数减去上限，并提示把归并和新增一起提交。正文与版本原样保留。

## 召回、归属与开关

<a id="case-09"></a>

### 09 新会话先收到个人全文和项目目录，读取后才收到项目正文

- **类型** 集成测试（受控模型）。
- **目的** 验证两层读取确实发生在不同模型请求。
- **怎么测** 准备个人偏好和同仓库项目笔记，两者用不同的可识别文字。新会话发「补集成测试」。检查第一个请求有个人正文及其字符用量、目录及其条数与 UTF-8 字节用量，各用量均含上限。项目笔记独有细节在 `read` 后的请求中随工具结果出现，调用编号配对。

<a id="case-10"></a>

### 10 同一仓库的 worktree 共用项目记忆

- **类型** 集成测试。
- **目的** 验证共享的范围是本机仓库。
- **怎么测** 为临时 Git 仓库建立 worktree。从主目录会话写入一条项目约定，再从 worktree 对应的会话准备输入。检查两处指向同一个记忆项目，worktree 能看到该目录项。

<a id="case-11"></a>

### 11 独立克隆各自保持项目记忆

- **类型** 集成测试。
- **目的** 验证同一个远端的两个本机克隆也各自保存。
- **怎么测** 用本机临时仓库建立两个独立克隆。在 A 保存一条项目记忆，分别准备 A 和 B 的模型输入。检查 A 能看到条目，B 的目录无此条目。让 B 按 A 的笔记路径请求 `read`，核对工具拒绝跨项目读取。

<a id="case-12"></a>

### 12 已打开会话的下一条消息看到新项目目录

- **类型** 集成测试（受控模型）。
- **目的** 验证目录按用户消息刷新，而一条消息里的模型调用共用目录。
- **怎么测** 在同一个项目打开两个会话。B 第一轮读取目录后暂停在工具阶段，A 保存一条新笔记。让 B 继续发起该轮第二次模型调用，检查目录及用量维持该轮版本。B 下一次收到用户消息时，检查第一个模型请求已带新条目及新用量。

<a id="case-13"></a>

### 13 压缩成功后已有会话重读个人记忆

- **类型** 集成测试（受控模型）。
- **目的** 验证个人全文的既定刷新时点。
- **怎么测** 让会话 A 加载旧个人文档，另一路保存字数不同的新版本。压缩前核对 A 沿用旧全文及其字符用量。完成一次成功压缩后再发消息，核对模型收到新全文及新用量。

<a id="case-14"></a>

### 14 关闭后的下一条消息省去记忆并保留原聊天

- **类型** 集成测试（受控模型）。
- **目的** 验证开关对旧会话和历史工具结果生效。
- **怎么测** 在旧会话先加载个人全文、项目目录并用 `read` 打开一篇笔记，再触发一次带有最新个人条目的超限回执。在设置关闭后，回旧会话发新消息并触发一次压缩。核对主模型与摘要模型的请求省去记忆内容，包括旧 `read` 正文、`memory` 调用参数和回执中的条目。主模型请求也省去个人全文、目录、用量和 `memory` 工具。工具调用仍配对，网页保留原聊天和工具结果，磁盘记忆仍可管理。

<a id="case-15"></a>

### 15 普通任务访问时删除到期的项目笔记

- **类型** 集成测试。
- **目的** 验证明确到期的项目事实自动退出召回。
- **怎么测** 准备一条已到期的发布冻结项目记录和一条仍有效的项目记录。在记忆开启的普通模式下发起任务。检查到期笔记已从磁盘和目录移除，仍有效的记录可以查到。

<a id="case-16"></a>

### 16 只读任务跳过到期笔记并保留文件

- **类型** 集成测试。
- **目的** 验证只读情况下的过期处理和文件状态。
- **怎么测** 预置一条已到期的项目笔记，在记忆开启的只读会话发消息。检查本轮目录跳过到期条目，调用读取得到到期提示，磁盘文件保持原样。

<a id="case-17"></a>

### 17 目录超出 200 条时只提供前 200 条

- **类型** 单元测试。
- **目的** 验证手工维护的目录超限时，模型输入仍按条数上限收口。
- **怎么测** 从磁盘预置超过 200 条且不足 24,000 UTF-8 字节的有效笔记目录。核对返回整行的前 200 项，完整目录仍可在设置查阅。

<a id="case-18"></a>

### 18 目录超出 24 KB 时保留限额内的完整行

- **类型** 单元测试。
- **目的** 验证多字节文字按实际字节数计量。
- **怎么测** 从磁盘预置不足 200 条、含中文且跨过 24,000 UTF-8 字节的目录。核对首个越界目录行没有部分显示，留下的字节均能按 UTF-8 解码，条数和字节上限同时满足。用量提示按裁剪前的完整有效目录显示。

## 个性化管理

<a id="case-19"></a>

### 19 用户摘要保存的 Markdown 进入新会话

- **类型** 端到端测试（Chromium，受控模型）。
- **目的** 在一次操作中核对编辑、实际落盘和下一会话获取的数据。
- **怎么测** 在「设置 → 个性化」打开「用户摘要」，核对展示的是已保存的正文。把偏好改为「解释设计时先说我会看到什么」并保存。读取实际个人文档，再开一个项目会话，对照首个模型请求中的个人记忆正文与编辑器保存结果。

<a id="case-20"></a>

### 20 项目摘要只列有条目的项目并提供目录地址

- **类型** 集成测试（Chromium）。
- **目的** 验证折叠组的条数和文件地址来自实际存储。
- **怎么测** 准备有笔记的 A、A 的 worktree、空记忆的 B。打开「项目摘要」，展开 A。核对 A 只出现一组，条数与完整目录一致，每项标题、简述和文件地址与磁盘对应。本机地址可复制，面板输入和展示均只需目录。

<a id="case-21"></a>

### 21 点叉删除最后一条后移除该项目

- **类型** 端到端测试（Chromium）。
- **目的** 确认界面操作确实删除对应文件并影响后续召回。
- **怎么测** 给 A 留一条项目笔记，在「项目摘要」展开 A 后点该目录项的 ×。等服务端返回后检查条目、目录链接和文件均已移除，A 从项目列表退出。再从 A 发下一条任务，核对目录已没有被删除的条目。

<a id="case-22"></a>

### 22 个人摘要版本冲突时保留编辑草稿

- **类型** 集成测试（Chromium）。
- **目的** 验证用户编辑工作和新写入都受到保护。
- **怎么测** 打开用户摘要并改写一段，先让另一会话保存新的个人条目，再点击弹窗「保存」。核对网页显示版本冲突并保留草稿，重读看到另一会话写入的版本。

## 真实任务闭环

<a id="case-23"></a>

### 23 真实模型按上下文保存、跨会话使用并核对出处

- **类型** 端到端测试（网页、真实模型）。
- **目的** 用生产入口证明从消息、写入、召回到用户可观察结果的整条链路。
- **怎么测** 使用临时 Git 仓库和真实模型。在网页分别用「可以」确认一次性操作和一项长期测试约定。检查一次性操作完成且记忆为空，长期约定真实落盘并带有写入会话与时间。另开同项目会话，先问怎么准备集成测试，核对出站目录、按需读取的笔记正文和回答中的约定。再查出处，核对 `memory_source` 的调用与回填以及用户原话。

## 个人记忆满额归并

<a id="case-24"></a>

### 24 个人记忆归并和新增一起保存

- **类型** 工具和存储集成测试（受控模型）。
- **目的** 验证普通新增超限后，同主题归并和新增可以由同一个 `memory` 工具完成。
- **怎么测** 准备一份接近上限的 `USER.md`，其中两条讲解偏好部分重叠且各有来源。模拟模型收到新增超限回执后，把归并更新、移除被归并条目、新增其他协作偏好一起提交。核对工具返回 `saved` 和本次修改已完成的提示，包含全部改动。余下的讲解偏好保留两条来源，新偏好保留本轮来源，全文符合上限。

<a id="case-25"></a>

### 25 归并后的全文仍超限时保留原文件

- **类型** 工具和存储集成测试。
- **目的** 验证这组修改按最终字数检查，超限时整批留在原状。
- **怎么测** 用两条可归并的个人记忆准备同一次更新、删除和新增，但让待新增条目较长，归并后仍超过上限。核对返回 `capacity_exceeded` 和结束这次新增的提示，结果只含超限摘要。文件正文、版本和来源与提交前一致，新增条目未落盘。

<a id="case-26"></a>

### 26 待归并条目版本已变化时整批失败

- **类型** 工具和存储集成测试。
- **目的** 防止归并使用旧内容覆盖其他会话的修改。
- **怎么测** A 按版本 1 准备归并请求。B 先更新其中要被移除的条目。A 提交旧请求时核对返回 `version_conflict`，文件与 B 保存后的内容一致，A 的归并更新、删除和新增都没有落盘。

## 项目记忆容量

<a id="case-27"></a>

### 27 项目写满 200 条后拒绝新增且继续当前任务

- **类型** 会话和工具集成测试（受控模型）。
- **目的** 验证按最终条数限制新增，容量失败后模型能继续本轮。
- **怎么测** 准备 199 条有效项目笔记，目录与每篇笔记均低于大小上限。先成功写入第 200 条，再在处理正常任务时提交第 201 条。核对工具回执说明超 1 条，实际存储仍是原有 200 条。按原调用编号把结果交回模型，核对本轮没有因超限终止，仍能继续调用工具并完成回复。随后更新一条现有笔记，目录和笔记大小合规时应保存。

<a id="case-28"></a>

### 28 目录超出 24 KB 时拒绝更新

- **类型** 工具和存储集成测试。
- **目的** 验证更新摘要也按最终目录的 UTF-8 大小检查。
- **怎么测** 准备不足 200 条的项目目录。更新一个中文摘要使完整目录恰好 24,000 字节，核对成功。再次更新使目录达到 24,001 字节，核对回执指出目录超限 1 字节，目录和旧笔记版本保留。

<a id="case-29"></a>

### 29 单篇笔记超出 4 KB 时拒绝更新

- **类型** 工具和存储集成测试。
- **目的** 验证单篇容量包含正文和元数据。
- **怎么测** 用含中文的笔记更新到整篇恰好 4,000 UTF-8 字节，核对成功。保持目录大小合规，再尝试使包含文件头的整篇笔记达到 4,001 字节。核对回执指出单篇超限 1 字节，已保存正文和版本保留。

## 已有会话与来源边界

<a id="case-30"></a>

### 30 已有会话重新开启后读取最新记忆

- **类型** 会话集成测试（受控模型）。
- **目的** 验证关闭期间的修改在重新开启后的首个任务生效。
- **怎么测** 让已有会话先加载个人全文和项目目录，再从设置关闭记忆。用设置编辑个人全文并删除一条项目记忆，然后重新开启。这段时间原会话不发消息。回原会话发下一条消息，核对个人全文、项目目录和各自用量都来自最新内容，可写模式中再次声明 `memory`。

### 31 记忆来源回查遵守项目和写入时间边界

- **类型** 会话和工具集成测试（受控模型）。
- **目的** 验证程序记录出处，并按已保存的记忆条目授权回查。
- **怎么测** 用受控模型保存一条个人记忆，再给来源会话发一条后续消息。在同仓库另一个只读会话回查，核对保存前的原话和配对结果。在其他项目调用同一条目的回查，核对拒绝与历史隔离。关闭后检查下次模型输入省去原回查结果，网页仍可看历史。另核对分页、来源会话缺失、旧消息编号格式和直接手动编辑。
