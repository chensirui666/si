## 默认工具与权限

<a id="case-01"></a>

### 01 普通模式默认提供 Code Mode 与直接工具

- **类型** 集成测试。
- **目的** 核对首轮工具声明和模型实际可走的两种调用方式。
- **怎么测** 在新普通会话发消息，捕获模型首轮工具清单。检查同时含 `codemode`、`read` 和已获准的写工具。用受控模型直接调用 `read` 读取示例 `README.md`，核对原编号和结果。

<a id="case-02"></a>

### 02 只读模式可用脚本查找和读取

- **类型** 集成测试。
- **目的** 核对脚本绑定服从只读模式的工具清单。
- **怎么测** 启用一个受控 MCP 服务，在只读会话运行一段程序，先列出可用绑定，再查找并读取示例 `notes/guide.md`。检查真实读取结果，工具绑定缺少写入和普通 Bash 入口，脚本查询 MCP 工具时得到空列表。

<a id="case-03"></a>

### 03 计划模式保留 Git 参数限制

- **类型** 集成测试。
- **目的** 核对脚本内调用使用计划模式的 Git 命令限制。
- **怎么测** 在临时 Git 项目的计划会话中运行脚本，依次尝试 `git status --short` 和 `git add sample.txt`。检查前者返回真实状态，后者给出拦截原因，暂存区保持原样。

<a id="case-04"></a>

### 04 运行中切到只读会拦截后续写入

- **类型** 集成测试。
- **目的** 核对每次子调用实际执行前都会检查最新权限。
- **怎么测** 在普通会话中发起脚本，先等待一个可控读取，再尝试写 `notes.txt`。读取开始后将会话切到只读并等服务端确认。释放第一次读取。核对读取结果保留、写入被拦截、`notes.txt` 内容未变化，拒绝原因落在相应子调用。

<a id="case-05"></a>

### 05 文件保护 Hook 会拦截内部编辑

- **类型** 集成测试。
- **目的** 核对程序里的编辑也经过文件保护扩展。
- **怎么测** 加载现有路径保护扩展，在临时项目放置含测试值的 `.env`。让脚本用 `edit` 尝试修改，等待调用结束。检查文件内容、未执行原因和相同子调用编号的记录。

## 执行与回填

<a id="case-06"></a>

### 06 按查找结果选择文件并回填片段

- **类型** 集成测试（实际 Pi SDK，受控模型）。
- **目的** 核对脚本可以消费一次工具的结果决定下一个工具参数。
- **怎么测** 在同一工作区准备三个文件，其中目标文件名以 `current` 开头。受控模型提交脚本查找三个候选，从结果选中目标并读取，然后只交回第一行。核对实际读取路径、内部调用记录及第二次模型请求。结果按原 `codemode` 编号回填一次。

<a id="case-07"></a>

### 07 一项并行调用失败后脚本可汇总成功项

- **类型** 集成测试（实际 Pi SDK）。
- **目的** 核对程序可以捕获单项失败并保留其他结果。
- **怎么测** 用同一程序并行读取一个存在的文件和一个刚被移除的文件。用各项独立结算取得成功文本与失败原因，再汇总。检查两个子调用分别结算，程序交回的汇总与真实情况一致。

<a id="case-08"></a>

### 08 批量前台委派部分失败仍保留每项结果

- **类型** 集成测试（受控子会话，依赖 Feature 12）。
- **目的** 核对批量前台委派允许程序处理部分成功。
- **怎么测** 在一批前台委派里让第一项返回 `{ "module": "MCP", "issues": [] }`，第二项产生可控失败。检查程序获得按请求排列的两项结果，能使用第一项答复并按对应 ID 标记第二项失败。

## 运行限度与停止

<a id="case-09"></a>

### 09 请求超过十分钟会在启动前被拒绝

- **类型** 单元测试。
- **目的** 核对外层运行时限的输入校验。
- **怎么测** 提交含一次工具调用的脚本，设置 `timeoutMs: 600001`。核对返回时限错误、未取得执行名额、目标工具未运行。默认值检查同时确认省略时使用 300000 毫秒。

<a id="case-10"></a>

### 10 超时保留已产出的内容并收尾

- **类型** 集成测试（实际 Pi SDK）。
- **目的** 核对超时信号覆盖程序等待工具的时间。
- **怎么测** 脚本先输出「已找到文件」，再等待一个可取消的慢工具。指定短时限。核对取消信号送达、工具收尾记录、外层超时原因和已有输出。后续模型请求收到已保存的外层结果。

<a id="case-11"></a>

### 11 用户中止后已开始的调用按实际结果结算

- **类型** 集成测试。
- **目的** 核对用户中止和工具自身的实际执行结果都能反映在记录中。
- **怎么测** 让脚本先完成一次读取，再开始可控慢工具。通过现有停止入口请求中止，随后释放慢工具的收尾。检查成功读取仍显示成功，慢工具显示其实际取消状态，任务在收尾后变为空闲，主模型没有进入下一次请求。

<a id="case-12"></a>

### 12 已接单的后台 Bash 在程序超时后仍可管理

- **类型** 集成测试（实际 Bash 进程）。
- **目的** 核对已接单的后台作业沿用现有会话归属和停止规则。
- **怎么测** 让程序启动临时后台 Bash 并取得作业编号，再等待一个受控工具直至程序超时。检查 Bash 的子调用已成功、该作业仍可在原会话查询，并用现有停止入口清理作业。

## 记录和展示

<a id="case-13"></a>

### 13 开始记录保存失败时工具不执行

- **类型** 集成测试。
- **目的** 核对修改文件前必须先保存调用记录。
- **怎么测** 对内层 `write` 注入 SQLite 开始记录写入失败。检查文件内容保持原样，工具执行次数为零，页面收到保存失败状态。

<a id="case-14"></a>

### 14 修改后缺少终态的调用重启后显示结果未知

- **类型** 集成测试（临时 SQLite 会话库）。
- **目的** 核对服务中断后能看到可能已发生的动作。
- **怎么测** 先确认开始记录保存，再让 `write` 修改测试文件。在提交子调用结果前中断会话服务。复用原库启动，检查目标路径、父子关联和「结果未知」。从网页发送续做消息，捕获模型请求，核对原外层调用的恢复提示指向实际目标。检查测试文件的新内容，用它确认外部状态。

<a id="case-15"></a>

### 15 刷新后继续查看外层下方的独立工具行

- **类型** 组件测试（Chromium）。
- **目的** 核对工具行缩进及服务端快照恢复的实际显示。
- **怎么测** 挂载聊天组件，加载一条运行中的 Code Mode 及两项子调用。先让一项成功，另一项运行。重新挂载并用同一份服务端快照恢复，核对两项各处于外层下方、可单独展开且状态匹配快照。

## 脚本内 MCP 发现

<a id="case-16"></a>

### 16 脚本发现并调用未直接声明的 MCP 工具

- **类型** 集成测试（实际 Pi SDK、受控 MCP 服务及模型）。
- **目的** 核对脚本能在同一次运行中使用目录里的工具，继续沿用直接工具加载规则。
- **怎么测** 启用提供 `lookup_ticket(id)` 的受控 MCP 服务，在还没加载该工具的普通会话提交脚本。用 `searchTools` 查找，用 `describeTool` 核对 `id` 参数，再调用查到的工具读取 `T-42`。核对实际 MCP 请求、父子调用记录和回填结果。检查调用前及下一次模型请求的直接工具清单，以确认脚本内活动的生效范围。

<a id="case-17"></a>

### 17 搜索后服务停用会在发送前拦截

- **类型** 集成测试（实际 Pi SDK、受控 MCP 服务）。
- **目的** 核对脚本持有旧的工具绑定时，实际发送仍依据当前服务状态。
- **怎么测** 脚本找到 `lookup_ticket` 后通过受控工具暂停，停用该 MCP 服务，再释放程序触发调用。检查服务收到的 MCP 请求数为零，脚本收到失败原因，父工具行下的子调用记录显示实际状态。

## 真实任务

<a id="case-18"></a>

### 18 真实模型用 Code Mode 筛选项目文件并继续作答

- **类型** 端到端测试（Chromium、真实模型、实际 Node 后端）。
- **目的** 证明模型能通过网页入口写出可用脚本，并使用返回片段继续任务。
- **怎么测** 在真实项目选一个目标文件和多个候选。请模型先查找候选，再根据返回路径读取目标，只返回与问题相关的片段。核对程序和工具记录，确认读取路径来自查找结果，主模型后续请求收到选中内容并据此完成答复。

<a id="case-19"></a>

### 19 真实子 Agent 的结构化答复经校验后回填

- **类型** 端到端测试（Chromium、真实主模型和子模型，依赖 Feature 12）。
- **目的** 证明程序能用多个实际答复做校验、汇总与分支。
- **怎么测** 在真实项目选定三个模块并提供一次性检查角色。任务约定返回 `module` 和 `issues`，其中一项要求使用无效结构以核对异常分支。让主模型写程序等待前台委派、按任务核对模块和问题列表。检查子会话真实工作、程序保留有效结果并标注需复核的项。核对有问题时和无有效问题时采用的分支，以及主模型使用了最终汇总。

<a id="case-20"></a>

### 20 真实模型在同一脚本内发现并调用 MCP 工具

- **类型** 端到端测试（Chromium、真实模型、实际 MCP 服务）。
- **目的** 证明当前会话可以用一次程序完成首次 MCP 查找、调用和结果筛选。
- **怎么测** 从新会话发一条查询任务，选择已配置且支持只读查询的真实 MCP 服务。请模型用 Code Mode 查询工具、查看参数、执行查询并带回用户所需字段。核对首次模型请求的工具声明、脚本使用的搜索与调用、子工具行和下一次模型输入。用服务的实际返回核对最终答复。

## 执行说明

- **既有覆盖**　直接工具的权限切换、中止、SQLite 恢复和工具状态 UI 有既有测试。实现后先复跑这些覆盖，再运行本页新增案例。 [会话权限与停止测试](../../../packages/coding-agent/test/agent-session.test.ts) · [会话存储测试](../../../packages/coding-agent/test/session-store.test.ts) · [聊天工具状态测试](../../../web/src/components/AssistantMessage.test.tsx)
- **运行方式**　按开发指南先校验受影响的 Agent、Coding Agent 和网页。受控测试用于核对输入边界、保存顺序和停止结果。真实模型案例需要同时证明模型决定、实际执行、UI 及后续模型输入，因此使用端到端测试。记录密集调用下逐条保存的实测耗时和线程名额退出后能否复用。 [校验命令](../../../docs/development.md#校验)
- **真实环境**　使用临时工作区和临时会话库，从现有测试凭据入口明确提供所选模型。真实子 Agent 验收需要已接入 Feature 12 的前台委派。真实 MCP 验收复用 Feature 5 的服务与凭据入口。凭据或能力缺失时，记录对应案例和原因。 [Feature 12 技术设计](../feature12/feature12-Multi-Agent技术设计.md) · [Feature 5 MCP 验收记录](../feature5/feature5-MCP客户端验收记录.md) · [真实模型验收条件](../../../docs/development.md#L71)
