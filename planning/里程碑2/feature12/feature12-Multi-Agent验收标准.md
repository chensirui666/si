## 角色发现和授权

<a id="case-01"></a>

### 01 个人角色提供摘要并按文件配置启动

- **类型** 集成测试。
- **目的** 确认摘要、角色正文、工具和模型各自出现在正确位置。
- **怎么测** 在个人目录写入 `test-reviewer.md`，正文带独有标记，再声明只读工具及一个已配置模型。检查主模型实际收到的角色目录只有名称和用途。指定该角色委派，核对标记随角色正文追加到子会话系统提示，第一条用户输入采用 `Task: …` 并传入本次问题，子模型和工具采用实际获准的配置。 [Pi 追加角色与提交任务](../../../pi/packages/coding-agent/examples/extensions/subagent/index.ts#L420)

<a id="case-02"></a>

### 02 旧工作区默认关闭项目角色

- **类型** 集成测试。
- **目的** 验证迁移保留原工作区身份并使用默认授权值。
- **怎么测** 用缺少 `projectAgentsEnabled` 的记录打开一个项目，其中放置角色文件。核对 ID 和目录仍能使用，主模型目录只包含个人角色。直接请求该项目角色时返回授权原因。

<a id="case-03"></a>

### 03 开启项目角色后同名文件采用项目定义

- **类型** 集成测试。
- **目的** 验证项目角色作用域及同名优先级。
- **怎么测** 个人与当前项目各保存 `reviewer.md`，用途字段分别写「个人」和「项目」。在工作区记录开启项目角色，核对下一次摘要和默认委派选中项目版本。显式把 `agentScope` 限定为 `user` 时选中个人版本。

<a id="case-04"></a>

### 04 同一轮修改角色文件后下一次请求看见新版

- **类型** 集成测试。
- **目的** 确认角色列表每次组装请求时更新。
- **怎么测** 让主模型先看到旧用途，在一次工具调用中改写、增加和删除角色文件。核对同一轮的下次模型请求采用最新目录。再次改写已选角色正文，然后启动子会话，核对实际加载启动时的版本。

<a id="case-05"></a>

### 05 主模型选中角色后关闭项目授权，派发返回失败

- **类型** 集成测试。
- **目的** 确保启动时以当前来源工作区授权为准。
- **怎么测** 主模型读到项目角色后、服务端接单前，将对应开关改为 `false`。维持主会话工作目录，并传另一个已存在的 `cwd`。核对工具返回项目角色未启用，子模型调用次数为零。

<a id="case-06"></a>

### 06 已有项目子会话在关闭授权后拒绝续用

- **类型** 集成测试。
- **目的** 确认保存的角色配置仍受来源工作区的当前授权约束。
- **怎么测** 先开启项目角色并完成一轮，再关闭该角色来源工作区开关，对原 `sessionId` 调用 `continue`。核对工具返回授权原因，已有历史可恢复，追加的模型请求为零。

### 07 通用子 Agent 使用指定目录和继承模型

- **怎么测** 省略角色，前后台各启动一次普通任务，用 `cwd` 指向含特定 `AGENTS.md` 的临时目录。检查两次实际子模型请求都包含基于 Pi P2 的通用指令，交代子 Agent 身份、简洁作答、结果回报和 `team` 的用途。核对项目说明来自实际任务目录，模型与推理级别沿用主会话。 [Pi P2 通用指令](../../../pi/apps/p2/plugins/subagents/tools.ts#L581)

### 08 无效工作目录的委派返回路径错误

- **怎么测** 对通用子 Agent 指定一个不存在的本机目录。核对工具返回路径错误，子模型调用为零，后续正常请求可以继续启动。

### 09 SI 先读创建指南再保存可复用角色

- **怎么测** 在临时工作区放置一个同名 `docs/subagents.md`，并提出「创建个人子 Agent `test-reviewer`，负责检查测试缺口」。核对系统提示给出 SI 应用内的指南绝对路径。模型先读应用指南，再在临时个人目录写入包含名称、用途和正文的 Markdown。下一次主模型请求能看到该角色摘要，可按名称调用。 [同类 Skill 文档路径验收](../../../web/tests/e2e/skills.spec.ts#L63)

## 任务委派与并发

<a id="case-10"></a>

### 10 前台单个子任务的结果回填原调用

- **类型** 集成测试。
- **目的** 确认主模型等子任务结束并使用其真实结果。
- **怎么测** 阻塞子模型生成，调用前台 `run`。核对主模型没有提前开始下一次请求。子模型完成文件读取和报告后，主模型收到对应工具调用编号的结果，能够引用报告中的实际信息。

<a id="case-11"></a>

### 11 并行任务保留输入顺序和部分失败

- **类型** 集成测试。
- **目的** 确认结果聚合与完成顺序无关。
- **怎么测** 发起两个 `tasks`，分别使用不同角色和模型。让第二项先成功，第一项稍后失败。核对两项确实重叠执行，完成结果按原输入顺序返回，一项失败没有覆盖另一项真实结果。

<a id="case-12"></a>

### 12 同一批工具调用可并行新建 A 并续用 B

- **类型** 集成测试。
- **目的** 确认一次主模型回复能调用同一个工具的两个动作。
- **怎么测** 预置空闲子会话 B。让主模型在同一次回复发出前台 `run` 创建 A，同时发出前台 `continue` 续用 B。核对两轮重叠执行，分别向自己的工具调用编号回填，B 沿用自己的历史。

<a id="case-13"></a>

### 13 串行步骤只用紧邻上一步的结果

- **类型** 集成测试。
- **目的** 确认 `{previous}` 的替换位置和执行顺序。
- **怎么测** 编排三项。首项返回 `A`，第二项读取 `{previous}` 并返回 `B`，第三项读取 `{previous}`。核对每项仅在前一步成功后启动，第三项得到 `B`，工具结果给出最后一项的答复。

<a id="case-14"></a>

### 14 串行中间项失败后后续项保持未启动

- **类型** 集成测试。
- **目的** 确认失败时能定位步骤并保留已完成结果。
- **怎么测** 让三项串行的第二项明确失败。核对第一项结果已保存，第二项标明失败，第三项保持「未启动」，其角色和模型未被调用。

<a id="case-15"></a>

### 15 两个后台续用竞争同一目标时只有一个成功接单

- **类型** 集成测试。
- **目的** 确认回执对应目标已保存的一轮。
- **怎么测** 同时从主 Agent 的 `subagent.continue` 和同伴的 `team.continue` 续用 `reviewer`。在保存接单前设置屏障，核对两边都没有成功回执。分两组让两个工具各赢一次，胜方接单后保持目标运行。核对每组只保存一个新输入和运行编号，胜方收到该编号，败方收到「正在运行」，且它的输入没有入队。

<a id="case-16"></a>

### 16 目标已有待发消息时续用保持原队列顺序

- **类型** 集成测试。
- **目的** 确保续用不会占据用户已经排好的下一轮。
- **怎么测** 让主会话旧轮结束并保留待发的「改 README」，在领取队首前由子 Agent 尝试 `team.continue`。核对返回「已有待发任务」，下一次启动读取原队首，续用请求没有加入或越过该队列。

<a id="case-17"></a>

### 17 前台创建后台续用再前台续用共用同一历史

- **类型** 集成测试。
- **目的** 确保等待方式属于当前调用，历史属于子会话。
- **怎么测** 前台创建子会话并让它从文件得到唯一标记 `login-v2`。再用同一个 `sessionId` 后台续用一次，并在报告送达后前台续用。核对三次执行有不同运行编号并追加在同一个会话，后两轮可以引用此前标记。

<a id="case-18"></a>

### 18 同一主会话的多批任务和续用共享 8 个名额

- **类型** 集成测试。
- **目的** 确认并发检查和登记在抢最后一个名额时仍有效。
- **怎么测** 发起两个各 4 项的并行批次并占满 8 个名额。核对新的 `run` 或启动子会话的 `continue` 返回容量状态。让一项停止并在收尾处暂停，核对该项仍计数。释放收尾后让两个请求竞争最后一个名额，仅一个成功。另一个主会话仍可独立接单。

## Agent 间协作

从实际工具调用核对三处证据。发起方的工具结果关联原调用，接收方的保存记录包含来源和运行编号，接收方的实际模型请求证明何时读到了消息。用测试屏障控制接单、工具返回和收尾顺序。

| 接收方 | `continue` | `steer` |
| --- | --- | --- |
| 空闲且可以开新轮 | 前台等待答复，后台确认接单后回执。见 [同伴前台续用](#case-35)、[同伴后台续用](#case-36)、[续用直属主会话](#case-24)。 | 返回空闲。见 [空闲插话](#case-21)。 |
| 空闲但有待发任务或待审核 | 返回实际原因，保持原有处理顺序。见 [待发任务](#case-16)、[计划审核](#case-38)。 | 当前没有可插话的运行。见 [空闲插话](#case-21)。 |
| 正在运行 | 返回正在运行。见 [并发抢接单](#case-15)、[主会话正在等待](#case-31)。 | 接收后立即回执，下一步交给同一轮。见 [工具批次收尾](#case-20)、[纯文字答复收尾](#case-33)。 |
| 正在停止 | 返回正在停止。见 [停止时续用](#case-32)。 | 返回正在停止。若早已接收但停止前未交给模型，则标记未交付。见 [停止时插话](#case-22)、[已接收后停止](#case-23)。 |

<a id="case-19"></a>

### 19 主会话和子会话各自获得对应的协作工具

- **类型** 集成测试。
- **目的** 确认服务端校验与模型工具目录一致。
- **怎么测** 记录一个主会话和所属子会话的实际模型工具定义。核对两类会话各自只获得对应工具，模型看到的动作、参数和运行条件与 SI 的 `continue` 和 `steer` 协议一致。分别让受控模型尝试调用未注册的工具，核对工具调用失败，目标的输入、队列和运行记录没有变化。

<a id="case-20"></a>

### 20 两个工具插话都在当前工具批次结束后送达

- **类型** 集成测试。
- **目的** 确保接收方的实际模型请求和工具回执一致。
- **怎么测** 让 `reviewer` 在同一步调用两个工具，将最后一个工具暂停。依次从主 Agent 用 `subagent.steer`、从同伴用 `team.steer` 提交不同的消息。核对接收会话已保存插话才回执，回执关联同一个目标运行编号。放行前无下一次模型请求。放行后，下一次请求带齐本批工具结果和按接收顺序排列的两条插话，各出现一次，发送者身份正确。

<a id="case-21"></a>

### 21 目标空闲时插话返回实际状态

- **类型** 集成测试。
- **目的** 确保显式插话只关联当前运行。
- **怎么测** 在 `reviewer` 已完成一轮且空闲时分别调用两个 `steer`。核对两者均返回空闲，未创建新一轮，也没有遗留待发消息。

<a id="case-22"></a>

### 22 目标正在停止时插话返回正在停止

- **类型** 集成测试。
- **目的** 确认停止信号设置后显式插话不会转入下一轮。
- **怎么测** 阻塞 `reviewer` 的停止收尾，在停止信号已生效时发两种 `steer`。核对返回正在停止，旧轮和后来续用的新轮都没有收到这条插话。

<a id="case-23"></a>

### 23 已接收插话遇到交付前停止时标记未交付

- **类型** 集成测试。
- **目的** 验证接收回执和实际送达状态可以区分。
- **怎么测** 暂停目标的当前工具批次，提交带唯一标记的插话。收到接收回执后停止该轮，再用 `continue` 启动新的运行编号。核对原轮的插话标为「未交付」，两轮的模型请求中都没有该标记，新轮队列里也没有该插话。

<a id="case-24"></a>

### 24 子 Agent 用 parent 续用空闲主会话

- **类型** 集成测试。
- **目的** 验证直属主会话和前台结果配对。
- **怎么测** 主会话交办后台子 Agent 后空闲。子 Agent 调用 `team.continue`，传 `name: "parent"` 和 `background: false`。核对原主会话保留自己的历史，并收到标有该子 Agent 身份的新输入。阻塞主会话的新轮时，子 Agent 的原工具调用仍在等待。放行后核对主会话最终答复按原工具调用编号交回该子 Agent。

<a id="case-25"></a>

### 25 主工具状态与团队列表显示同一个子 Agent 的实际状态

- **类型** 集成测试。
- **目的** 确认两个查询入口使用同一会话状态。
- **怎么测** 在同一工作区的两个主聊天里各创建一个名为 `reviewer` 的子会话。让聊天 A 的 `reviewer` 运行。A 的主 Agent 调用无目标的 `subagent.status`，A 的同伴调用 `team.list`。核对两个列表中 `reviewer` 都指向 A 的同一个子会话 ID 和最新状态，B 的 ID 未出现，`team.list` 也不列出调用者自己。

<a id="case-26"></a>

### 26 团队读取同伴最近一次已完成的答复

- **类型** 集成测试。
- **目的** 确认查询可以返回已有结论，而不会开启新一轮。
- **怎么测** 同伴 B 已完成一轮，给出唯一结论 `checked-login`。让 B 的第二轮先输出一段带不同标记的文字，再在工具执行处阻塞。A 调用 `team.answer`。核对只返回第一轮结论，B 的当前运行编号和运行次数没有变化。

<a id="case-27"></a>

### 27 前台子 Agent 交回待决定事项后沿原会话继续

- **类型** 端到端测试（Chromium，受控模型）。
- **目的** 确认需要用户决定时主会话可以正确接回对话。
- **怎么测** 让前台 `reviewer` 报告已查文件并询问是否覆盖旧入口。主模型按 Feature 10 向用户提问。通过网页答复「要覆盖」后，核对主模型用原 `sessionId` 调用 `continue`，子 Agent 根据保留下来的工作继续。

<a id="case-28"></a>

### 28 跨聊天的子会话 ID 无法用于访问或发消息

- **类型** 集成测试（受控模型）。
- **目的** 验证执行时按主会话归属授权。
- **怎么测** 在同一工作区的聊天 A、B 都创建 `reviewer`。先用 A 的本地名称和本地 ID 各查询一次，核对定位到同一个 A 子会话。再从 A 主会话用 B 的子会话 ID 调用 `subagent.status`、`continue`、`steer`，从 A 子会话用该 ID 调用 `team.answer`、`continue`、`steer`。对读取、续用和插话分别设置 B 的状态，使请求若发生越权本可成功。核对每次都返回目标不可访问，没有泄露 B 的状态和答复，B 的输入、队列和运行记录均无变化。

<a id="case-29"></a>

### 29 同批前台子 Agent 可以边执行边交换发现

- **类型** 集成测试（受控模型）。
- **目的** 验证主会话等待整批结果时，两个前台子 Agent 仍能协作。
- **怎么测** 主会话用一次前台并行 `run` 启动 A 和 B。让 B 的当前工具暂停，只给 A 一个独有发现。A 通过 `team.list` 取得 B，再用 `team.steer` 送出发现。保持 B 阻塞时，核对 A 已收到接收回执并可结束，主会话仍等整批。放行 B 后，核对 B 在同一运行中读到 A 的发现并以它为依据回答，主会话只在整批结束后收到原调用的两个结果。

<a id="case-30"></a>

### 30 前台子 Agent 向正在等自己的主 Agent 插话

- **类型** 集成测试（受控模型）。
- **目的** 验证给直属主会话的插话回执不会依赖主模型先继续执行。
- **怎么测** 主会话用前台 `subagent.run` 等 A。A 调用 `team.steer`，指定 `name: "parent"` 并发送带标记的发现。核对主会话仍在等待时 A 已收到回执，主模型未发起新请求。再让 A 完成，核对主会话同一个运行的下一次模型请求同时包含原工具结果和署名 A 的插话，插话只出现一次。

<a id="case-31"></a>

### 31 主 Agent 等待子任务时拒绝该子 Agent 发起的续用

- **类型** 集成测试（受控模型）。
- **目的** 验证前台子任务无法让正在等待自己的主会话再开一轮。
- **怎么测** 让主会话用前台委派等待 A。A 调用 `team.continue`，指定 `name: "parent"`。前台与后台参数各执行一组，核对原工具调用立即得到「正在运行」，请求未入队且没有新轮。让 A 继续完成原任务，主会话收到原委派结果后正常推进。

<a id="case-32"></a>

### 32 两个续用入口均拒绝正在停止的目标

- **类型** 集成测试（受控模型）。
- **目的** 验证停止已开始但未收尾时，续用没有提前接单。
- **怎么测** 让 B 收到停止信号并停在收尾屏障。主会话用 `subagent.continue`，同伴 A 用 `team.continue`。核对均返回「正在停止」，两个输入均未写入历史或队列。放行收尾后再发一次合法续用，只有这次请求开启新轮。

<a id="case-33"></a>

### 33 纯文字答复收尾前已接收的插话进入同一轮下一步

- **类型** 集成测试（受控模型）。
- **目的** 验证原回复没有工具调用时，已接收的插话仍会交给模型。
- **怎么测** 让 B 正流式输出原本作为结尾的纯文字，在流结束前由同伴 A 提交 `team.steer` 并等到接收回执。结束原流，核对 B 在原运行编号下多发一次模型请求，该请求包含前一条纯文字答复和署名 A 的插话各一次。

<a id="case-34"></a>

### 34 重投同编号的插话返回原回执且不影响新轮

- **类型** 集成测试（受控模型）。
- **目的** 验证重复投递不能让同一条消息再次进入模型。
- **怎么测** 从 A 向 B 投递带唯一编号的 `team.steer`，让 B 消费插话并收尾。B 启动新轮后，通过内部接收入口重投相同编号和消息。核对返回原轮接收结果，存储中只有一条投递记录，新轮的模型请求没有重复出现这条输入。

<a id="case-35"></a>

### 35 前台续用同伴读取原历史并把答复交回调用者

- **类型** 集成测试（受控模型）。
- **目的** 验证同伴对同伴的续用具备完整的前台结果链路。
- **怎么测** 预置空闲 B 及仅存在于 B 旧历史的识别码。A 用 `team.continue` 前台续用 B。核对同一个 B 会话新增一个运行编号，首个模型请求包含 B 旧历史及带 A 身份的新输入。保持 B 阻塞时 A 的原调用继续等待。放行后核对使用该识别码的唯一结果按原工具调用编号交回 A。

<a id="case-36"></a>

### 36 后台续用同伴的完成报告只回到发起子会话

- **类型** 集成测试（受控模型）。
- **目的** 验证完成报告按本次发起者路由，和目标子会话的归属分开。
- **怎么测** A 用 `team.continue` 后台续用空闲 B；在 B 保存接单前阻塞，核对 A 尚未收到成功回执。保存后暂停 B 执行，核对 A 先收到回执并完成自己的当前轮。再让 B 完成，核对报告以本次委派编号只进入 A 一次，唤醒 A 原会话的新轮，供 A 模型读取。直属主会话无该条报告输入，A 原工具结果仍是接单回执。

<a id="case-37"></a>

### 37 同伴尚无已完成答复时查询不会触发执行

- **类型** 集成测试（受控模型）。
- **目的** 验证 `team.answer` 在无结果时仍是只读查询。
- **怎么测** 让 B 的首轮还在执行且已输出一段中间文字。A 调用 `team.answer`，核对返回尚无已完成答复，中间文字没有泄露，B 的运行、队列和模型请求数不变。

<a id="case-38"></a>

### 38 主会话待审核时子 Agent 续用不能绕过审核

- **类型** 集成测试（受控模型）。
- **目的** 验证内部协作也遵守接收会话的启动条件。
- **怎么测** 使主会话停在计划审核阶段，期间由已启动的后台子 Agent 调用 `team.continue`，指定 `name: "parent"`。核对工具返回待审核状态，计划仍待用户决定，没有新增主模型请求，也没有悄悄加入待发队列。

- **类型** 端到端测试（Chromium，真实模型）。
- **目的** 证明真实模型会选择角色、使用子工具并依据结果推进。
- **怎么测** 在临时工作区放入一段含可核对测试缺口的代码。通过网页先请 SI 创建个人 `test-reviewer` 角色，核对实际读到的指南和写入的角色文件。随后请主 Agent 用该角色审核，再让同一子 Agent 接着解释一个结论。核对实际工具参数、子会话读到的文件、工具回填、续用 ID，以及主模型的回答是否引用了真实发现。

<a id="case-60"></a>

### 60 真实模型通过 team 传递发现并据此完成前台协作

- **类型** 端到端测试（Chromium，真实模型）。
- **目的** 验证模型能够发现协作工具、选择正确接收方并使用对方给出的发现。
- **怎么测** 从网页请主 Agent 前台并行安排侦查和审查。只让侦查子 Agent 从自己的材料读取一个独有识别码，审查的初始输入不含该值。用测试屏障让审查保持运行以便接收插话，由真实模型生成 `team.list` 和 `team.steer` 调用及答复。核对实际工具调用找到了同批的审查子 Agent，审查模型在原轮收到带正确身份的识别码，并在最终答复中正确引用。主 Agent 从原委派调用读到两项结果并据此总结。
