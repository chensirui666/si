## 发现与更新

<a id="case-01"></a>

### 01 工作区子目录能发现祖先和嵌套的 Skill

- **类型** 单元测试。
- **目的** 验证向上找目录与向下找文件的两种规则。
- **怎么测** 在含 `.git` 的临时仓库选择 `apps/web`。分别在工作区 `.si/skills/`、`apps/.agents/skills/` 和仓库根 `.agents/skills/` 放入不同名称的 Skill，其中一项使用多级子目录。检查列表包含三个名称。另在某个已有 `SKILL.md` 的目录内部放一份参考 Markdown，检查列表没有参考文件条目。

<a id="case-02"></a>

### 02 项目和个人同名时采用项目版本

- **类型** 单元测试。
- **目的** 验证同名目录和加载使用同一份有效来源。
- **怎么测** 为当前工作区和测试个人目录创建同名 `review-changes`，分别写入不同用途和正文。查询时结果只含一项，描述与后续加载的正文均来自项目。更远的项目 `.agents` 同名时也采用更近的有效目录或优先的 `.si` 来源。

<a id="case-03"></a>

### 03 Pi 兼容的单文件说明能被发现

- **类型** 单元测试。
- **目的** 验证目录版之外已确认的兼容范围。
- **怎么测** 将各有有效描述的 `.md` 分别放到 `.si/skills/` 的直属位置和 `.agents/skills/` 的子目录。检查两项可发现，加载结果以各自父目录作为资源位置。

<a id="case-04"></a>

### 04 一个 Skill 目录读取失败时仍返回其他可用条目

- **类型** 单元测试。
- **目的** 验证目录故障时的局部恢复。
- **怎么测** 模拟一个根目录返回 `EACCES`，另一个根目录保留有效 Skill。确认有效条目正常且发现状态标记不完整。恢复目录读取后再次查询，确认能看到该根且不完整标记撤销。

<a id="case-05"></a>

### 05 格式错误的 Skill 不影响同目录正常条目

- **类型** 单元测试。
- **目的** 验证可用目录只展示有效说明。
- **怎么测** 在同一可读根下放一个缺少描述的 `SKILL.md`、一个 YAML 无法解析的 `SKILL.md` 和一个有效 Skill。检查只列出有效条目，并记录可用于排查的诊断。

<a id="case-06"></a>

### 06 新建 Skill 在下一次任务可用

- **类型** 集成测试（受控模型）。
- **目的** 验证正在运行的任务与下一条任务看到的目录。
- **怎么测** 让受控模型在普通会话的首轮写入 `new-review/SKILL.md`。检查本任务完成前下一次模型调用的目录仍为任务开始时的列表。结束后再次请求目录并提交下一条消息，检查目录接口和下一任务的模型输入都列出 `new-review`。

## 网页浏览与发送

<a id="case-07"></a>

### 07 新会话首发前可按所选工作区查询 Skill

- **类型** 集成测试（正式 HTTP 入口，受控模型）。
- **目的** 验证浏览不要求先创建会话。
- **怎么测** 登记两个临时工作区，分别准备不同 Skill。用已授权的页面请求相应工作区的目录接口，检查各自只返回对应条目及个人条目，响应仅携带摘要。查看会话列表仍为空。随后通过首发入口提交其中一项，检查服务器在目标工作区接收并加载。

<a id="case-08"></a>

### 08 工作区切换后忽略上一个工作区迟到的候选

- **类型** 组件测试。
- **目的** 确保草稿与候选都对应当前工作区。
- **怎么测** 打开 A 的菜单但延后 A 的查询结果，切到 B 再打开菜单。先返回 B 的目录，再返回 A 的目录。确认页面仍显示 B 的候选，草稿保持原样。

<a id="case-09"></a>

### 09 鼠标选择 Skill 只填入命令

- **类型** 组件测试（Chromium）。
- **目的** 验证菜单选择本身不发送消息。
- **怎么测** 在草稿中输入 `/` 并点击 `review-changes`。检查草稿为 `/skill:review-changes `，菜单关闭，发送回调调用次数为零。

<a id="case-10"></a>

### 10 按 Tab 选择 Skill 只填入命令

- **类型** 组件测试（Chromium）。
- **目的** 验证键盘补全和输入焦点。
- **怎么测** 在草稿中输入 `/`，用键盘选择 Skill 后按 Tab。检查命令填入、焦点回到或保留在输入框、发送回调调用次数为零。

<a id="case-11"></a>

### 11 输入法选字期间不会误选或误发 Skill

- **类型** 组件测试（Chromium）。
- **目的** 验证选字分支保护现有输入。
- **怎么测** 在命令输入区域触发合成选字事件，在选字尚未结束时按 Enter。检查消息未发送、Skill 未被误选。合成事件的结论限于防误发逻辑。

<a id="case-12"></a>

### 12 已有会话按命令和技能分组

- **类型** 组件测试（Chromium）。
- **目的** 验证同一 `/` 菜单分开显示内置命令和发现的 Skill。
- **怎么测** 在已有会话中输入 `/`。检查「命令」组在「技能」组之前，`/compact` 位于命令组，同名的 `compact` Skill 位于技能组。选命令时立即提交 `/compact` 并显示压缩记录。选 Skill 时填入 `/skill:compact `，前缀显示为蓝色，可编辑，选择本身不提交消息。

<a id="case-13"></a>

### 13 Skill 行显示实际采用的来源

- **类型** 组件测试（Chromium）。
- **目的** 验证技能行的标签对应实际可调用的版本。
- **怎么测** 用案例 02 的同名目录、一个仅在个人目录中的 Skill 和一个预置 Skill 打开菜单。检查同名项只出现一次并显示「项目」，其余两项分别显示「个人」和「预置」。移除项目的同名条目后重新打开菜单，检查同名项显示「个人」，并使用个人版本对应的用途。

<a id="case-14"></a>

### 14 Skill 查询失败时仍可选择命令

- **类型** 组件测试（Chromium）。
- **目的** 验证 Skill 查询和应用命令候选独立。
- **怎么测** 在已有会话中输入 `/`，让 Skill 目录请求失败。检查技能组给出重试提示。选择命令组的 `/compact` 后检查压缩请求正常提交。

## 加载、历史和权限

<a id="case-15"></a>

### 15 用户显式指定时首次模型请求已包含正文

- **类型** 集成测试（受控模型）。
- **目的** 验证加载确定发生且页面保留原文。
- **怎么测** 准备 `review-changes` 后提交 `/skill:review-changes 请复核改动`。检查首次模型请求包含当前正文、资源目录和用户要求，网页保留原提交文字并显示加载成功。

<a id="case-16"></a>

### 16 模型用现有 read 加载匹配的 Skill

- **类型** 集成测试（受控模型）。
- **目的** 验证目录只提供摘要，主动使用走现有工具。
- **怎么测** 准备一个可自动用的 Skill 和一个 `disable-model-invocation: true` 的 Skill。发送不含显式命令的任务，确认模型目录有前者的名称、描述和位置，后者仍在网页目录。让模型调用 `read` 后检查正文只随真实工具结果进入后续请求。

<a id="case-17"></a>

### 17 未知 Skill 命令按原文发送

- **类型** 集成测试（受控模型）。
- **目的** 验证未知名称可作为普通消息处理。
- **怎么测** 提交 `/skill:unlisted 请继续`，检查页面与模型均保留原文，加载记录未产生。

<a id="case-18"></a>

### 18 已找到的 Skill 读取失败时提示原因并继续

- **类型** 集成测试（受控模型）。
- **目的** 验证发现和实际读取之间的失败反馈。
- **怎么测** 让 `review-changes` 在扫描完成后、实际读取前被移走或变得不可读。检查页面显示读取失败，模型收到完整原文并继续。

<a id="case-19"></a>

### 19 重试或恢复仍对应本次加载的版本

- **类型** 集成测试（正式 HTTP 和 WebSocket 入口，受控模型）。
- **目的** 验证重新提交和恢复不会重复运行或重读旧调用。
- **怎么测** 加载正文 A 后丢弃首发回执，将磁盘正文改为 B，再用原编号原请求重试并重开会话。核对只运行一次、旧消息及模型回放对应 A。新消息显式调用后应读取 B。浏览器快照仅获得允许展示的加载结果。

<a id="case-20"></a>

### 20 压缩使用已记录的正文并估算其容量

- **类型** 单元测试。
- **目的** 验证会话摘要和容量计算使用相同的 Skill 历史。
- **怎么测** 准备带正文快照的显式调用和普通旧消息。检查保留窗口的估算考虑正文大小，构造摘要输入时使用保存的快照，旧消息保持原样。

<a id="case-21"></a>

### 21 只读 Skill 指令无法执行脚本或写入

- **类型** 集成测试（受控模型，复用权限覆盖）。
- **目的** 验证 Skill 只提供指令，工具仍按权限执行。
- **怎么测** 只读时读取相关 Skill 和配套文件，再让受控模型发出其中提到的 Bash 和 `edit` 调用。确认实际脚本未运行、文件未改，且错误与原工具调用配对。

## 创建、修改与再次使用

<a id="case-22"></a>

### 22 系统提示词指向 SI 自带 Skill 文档

- **类型** 集成测试（受控模型）。
- **目的** 验证普通模型输入只有文档入口，规则随读取结果进入。
- **怎么测** 在项目准备一个同名 `docs/skills.md`，并使用实际 SI 应用目录配置。发送创建请求，核对系统提示词的 `<docs>` 先列查阅时机、位置和主题，再说明创建或修改前用 `read` 完整查阅。检查规则正文随工具结果进入上下文，并且实际读到的是 SI 应用绝对路径下的文档。测试工作区可以没有任何可用 Skill。

<a id="case-23"></a>

### 23 范围未说明时先请用户选择

- **类型** 真实模型验收（沿用正式网页入口）。
- **目的** 核对模型询问时机以及实际文件效果。
- **怎么测** 在临时工作区和临时个人 Skill 目录均没有同名文件时，提出范围未定的新建请求。核对工具记录及磁盘路径，确认模型先询问项目或个人范围、这一轮没有文件改动。

<a id="case-24"></a>

### 24 用户选择项目范围时写到工作区

- **类型** 集成测试（受控模型）。
- **目的** 验证工作区内新建并读回。
- **怎么测** 在普通会话指定项目范围，让模型读取规则后用 `write` 创建并用 `read` 核对。检查实际文件在工作区 `.si/skills/<名称>/SKILL.md`。

<a id="case-25"></a>

### 25 用户选择个人范围时可从另一工作区发现

- **类型** 集成测试（受控模型）。
- **目的** 验证个人 Skill 的可见范围。
- **怎么测** 在普通会话指定个人范围，写入测试个人目录 `~/.si/skills/<名称>/SKILL.md` 对应的临时位置。切到不同工作区查询，检查 Skill 可见，两个项目目录均未写入对应文件。

<a id="case-26"></a>

### 26 新建遇到同名且路径未指定时先询问

- **类型** 真实模型验收（沿用正式网页入口）。
- **目的** 验证模型给出具体冲突位置并保留现有文件。
- **怎么测** 在测试工作区准备同名 Skill，再请模型新建且省略路径。检查回复给出已有来源和路径，并请用户选择修改或换名。核对工具记录和文件原样。

<a id="case-27"></a>

### 27 写入失败时反馈已确认的磁盘结果

- **类型** 集成测试（受控模型，复用本地工具覆盖）。
- **目的** 验证工具失败不会成为虚假的保存成功。
- **怎么测** 让 Skill 的目标目录不可写，尝试创建时检查 `write` 返回错误且文件未创建。若一项前置文件已写成功，核对路径与工具记录仍可查；后续恢复应先检查实际文件。

<a id="case-28"></a>

### 28 已有 Skill 在真实任务中发挥作用

- **类型** 端到端测试（Chromium、真实模型）。
- **目的** 核对现有 Skill 的指令确实被执行并影响真实结果。
- **怎么测** 实施时选一项已有 Skill 和一个符合其用途的真实工作任务，事先记下可观察的步骤与结果。走实际网页入口执行，核对记录中的正文读取、必要配套材料或脚本的实际结果，以及最终交付。

<a id="case-29"></a>

### 29 后续真实任务使用新建或修改的 Skill

- **类型** 端到端测试（Chromium、真实模型）。
- **目的** 证明新增或修改的规则能被发现并改变结果。
- **怎么测** 从已确认的实际需求选一项 Skill，通过网页使用 `/skill:skill-creator` 创建或修改。核对 Agent 查阅 SI 规则并读回操作后的文件。再提交另一条相关任务，核对读到的新版本与实际交付是否满足该 Skill 中可独立检查的要求。

## 首批 Skill

<a id="case-30"></a>

### 30 无用户自装 Skill 时能看到首批三个条目

- **类型** 集成测试（正式工作区查询入口）。
- **目的** 验证首批三个 Skill 随应用可用。
- **怎么测** 选择 SI 自己的检出作为工作区，清空测试项目和个人 Skill 目录。检查返回 `skill-creator`、`agents-md` 和 `grill-me`，来源为应用预置，正文可通过显式调用加载。

<a id="case-31"></a>

### 31 agents-md 更新当前仓库的项目说明

- **类型** 端到端测试（Chromium、真实模型）。
- **目的** 确认模型根据当前仓库的真实资料更新该仓库的说明。
- **怎么测** 将一个与 SI 不同的 Git 仓库的子目录选为工作区，使用 `/skill:agents-md` 更新一项可由仓库文件核对的开发命令。核对目标是所选工作区所属仓库根的 `AGENTS.md`，更新内容有实际命令定义支持，原有约定仍完整。另核对 SI 仓库的 `AGENTS.md` 内容与调用前一致。

<a id="case-32"></a>

### 32 grill-me 每轮只提出一个待决问题

- **类型** 端到端测试（Chromium、真实模型）。
- **目的** 确认模型按独立原版逐轮讨论设计取舍。
- **怎么测** 在只读会话用 `/skill:grill-me` 讨论一个实际方案，方案包含可从代码查到的现状和需要用户决定的取舍。检查模型先查现状，首轮只问一个待决问题并给出建议。回答后检查下一轮承接该决定。

<a id="case-33"></a>

### 33 修改预置 Skill 后优先使用个人副本

- **类型** 端到端测试（Chromium、真实模型）。
- **目的** 验证用户可修改预置 Skill 的副本，并在后续任务中使用。
- **怎么测** 在项目和个人均无 `grill-me` 同名版本的环境中，用普通模式要求修改预置 `grill-me`，选择个人范围。核对副本写到测试用户的 `~/.si/skills/grill-me/`，许可证随副本保留，应用预置文件内容与调用前一致。随后显式调用，核对使用的是个人副本及修改后的正文。
