## 工具范围

<a id="case-01"></a>

### 01 只读首轮仅提供四个工具且都可用

- **类型** 集成测试，受控模型，真实文件系统。
- **目的** 检查首轮声明和四个工具的实际能力。
- **怎么测** 在临时工作区准备 `README.md`、`.gitignore` 和 `src/index.ts`，后者包含文本「青禾」。以只读首发，捕获模型请求中的工具声明。让受控模型不传参数调用 `ls` 列工作目录、`find` 查找 `index.ts`、`grep` 搜索「青禾」并 `read` 读取该文件。检查声明恰好是这四个工具，目录结果包含隐藏项和 `src/`，其他三次调用分别返回真实路径、命中位置和正文。

<a id="case-02"></a>

### 02 只读模式拦截编辑调用并回填原因

- **类型** 集成测试，受控模型，真实文件系统。
- **目的** 检查未开放工具无法执行，结果与原调用对应。
- **怎么测** 在只读会话中，让受控模型发出参数有效的 `edit`，尝试把 `README.md` 中「原文」替换成「改过」。检查文件仍是「原文」，工具没有进入执行。下一次模型请求应同时包含原 `edit` 调用和使用相同调用编号的错误结果，内容说明只读模式下未执行。

<a id="case-03"></a>

### 03 切到普通后可以改文件和运行命令

- **类型** 集成测试，受控模型，真实文件系统和 Bash。
- **目的** 验证切到普通后恢复原有工具能力。
- **怎么测** 把只读会话切到普通，发送一条新消息。让受控模型先编辑临时文件，再运行 Bash 读出修改后的内容。检查模型收到现有工具和 `ls` 的声明，文件实际改变，Bash 输出与文件内容一致。

<a id="case-04"></a>

### 04 目录列表达到上限时说明截断

- **类型** 集成测试，真实文件系统。
- **目的** 检查目录工具的顺序和输出提示。
- **怎么测** 在工作目录创建 `c.txt`、`B.txt`、`a.txt`。调用 `ls`，传入 `path: ""` 和 `limit: 2`。结果按忽略大小写的顺序显示 `a.txt`、`B.txt`，并提示可以用 `limit: 4` 查看更多。

<a id="case-05"></a>

### 05 省略条数时最多列出 500 项

- **类型** 集成测试，真实文件系统。
- **目的** 使用 Pi 的默认条数。
- **怎么测** 在目录中创建 501 个短文件名。省略 `limit`，检查返回排序后的前 500 项，并提示可以用 `limit: 1000` 查看更多。

<a id="case-06"></a>

### 06 小数条数向下取整

- **类型** 集成测试，真实文件系统。
- **目的** 核对 Pi 对小数参数的处理。
- **怎么测** 在含三个文件的目录调用 `ls`，传入 `limit: 2.9`。检查只列出排序后的前两项，并提示可以用 `limit: 4` 查看更多。

<a id="case-07"></a>

### 07 小于 1 的条数按 1 处理

- **类型** 集成测试，真实文件系统。
- **目的** 避免把包含条目的目录误报为空。
- **怎么测** 在含三个文件的目录调用 `ls`，传入 `limit: 0`。检查列出排序后的第一项，并提示可以用 `limit: 2` 查看更多。

<a id="case-08"></a>

### 08 目录项数恰等于上限时完整返回

- **类型** 集成测试，真实文件系统。
- **目的** 避免给完整的列表加截断提示。
- **怎么测** 在含三个普通文件的目录调用 `ls`，传入 `limit: 3`。检查返回三项，结果里没有条数截断提示。

<a id="case-09"></a>

### 09 列表正文超过 50 KiB 时保留完整行

- **类型** 集成测试，真实文件系统。
- **目的** 验证字节上限及多字节文件名处理。
- **怎么测** 创建 300 个按序号开头、每个约 180 UTF-8 字节的中文文件名，使用默认条数。检查正文最多 50 × 1024 字节，保留按序排列且完整的前几行，每行均对应实际文件名，末尾提示字节截断。

- **目的** 检查空目录属于成功的列表结果。
- **怎么测** 创建空子目录，以相对路径调用 `ls`，检查返回空目录提示。

### 12 目录不可读时返回错误

- **类型** 集成测试，真实文件系统。
- **目的** 确认读取失败时返回原因。
- **怎么测** 以非管理员的普通测试进程读取一处可取得目录状态但没有列目录权限的临时目录。检查返回无法读取目录的错误。

- **类型** 集成测试，真实文件系统。
- **目的** 区分无效目录与空目录。
- **怎么测** 对临时工作区内的普通文件 `README.md` 调用 `ls`。检查返回目标不是目录的错误。

<a id="case-14"></a>

### 14 真实模型通过网页使用只读工具

- **类型** 端到端测试，Chromium、已配置且支持工具调用的真实模型。
- **目的** 核对正式网页入口、模型真实工具调用和用户可见结果。
- **怎么测** 在临时工作区准备带唯一标记的文件。通过实际网页选只读，请模型列目录并读取文件中的标记。核对会话工具记录和结果中的真实标记。验收记录写明使用的模型。受控测试不能代替这条真实链路。

## 会话切换

<a id="case-15"></a>

### 15 运行中切到只读后只拦截尚未开始的调用

- **类型** 集成测试，受控模型，实际 HTTP、订阅和文件系统。
- **目的** 证明权限按每次调用的实际开始时间生效。
- **怎么测** 在普通模式发出一批按顺序执行的调用。第一项命令启动后等待释放信号，第二项尝试编辑临时文件。等待第一项已启动，通过权限接口切到只读并收到确认，然后释放命令。检查第一项返回实际成功结果，第二项未开始且文件原文不变。两条结果各自对应原调用，下一次模型请求仅声明四个只读工具。

<a id="case-16"></a>

### 16 用户主动停止时正在运行的命令仍可中止

- **类型** 集成测试，实际 HTTP 与 Bash。
- **目的** 验证切换权限后的主动停止仍走现有收尾流程。
- **怎么测** 启动一个等待信号的命令，切到只读，确认命令仍在运行。然后向当前任务发送停止请求，检查命令结束、会话恢复空闲，随后等待的工具未启动。

<a id="case-17"></a>

### 17 同一会话的权限切换同步到两个页面

- **类型** 端到端测试，Chromium、实际 HTTP 与 WebSocket。
- **目的** 检查真实页面在同一会话下共享保存的模式。
- **怎么测** 两个页面打开同一普通会话。第二页从输入区切到只读，检查两个页面都只显示一个权限菜单，且无需重新发送消息就同步为只读。重新加载第一页，仍显示只读。

<a id="case-18"></a>

### 18 切换会话权限时另一个会话保留自己的模式

- **类型** 集成测试，实际 HTTP 和会话订阅。
- **目的** 检查权限变更仅作用于请求指定的会话。
- **怎么测** 在同一工作区创建两个普通会话，把其中一个切到只读。订阅两个会话并检查，目标会话是只读，另一会话仍是普通。

<a id="case-19"></a>

### 19 会话权限写入失败时保留原模式

- **类型** 集成测试，注入明确回滚的存储失败。
- **目的** 检查写入失败的回执、同步状态和执行权限一致。
- **怎么测** 在普通会话中使切换到只读的写入明确回滚。检查接口返回保存失败，重取会话快照仍是普通，随后获准的编辑能实际发生。

<a id="case-20"></a>

### 20 会话权限写入未确认时拦截新调用

- **类型** 集成测试，注入提交结果不明的存储失败。
- **目的** 检查会话在无法确认模式时暂停新的操作。
- **怎么测** 让普通会话的切换写入返回未确认，并让当前模型随后提出编辑。检查服务端提示核对状态，编辑执行次数为零，文件保持原状。

<a id="case-21"></a>

### 21 重启后恢复会话保存的权限

- **类型** 集成测试，实际 SQLite 和服务重启。
- **目的** 验证权限独立于页面和内存保存。
- **怎么测** 把正式会话切到只读并确认保存。重启服务，重新订阅同一会话。检查快照为只读，下一条消息给模型的声明仍是四个只读工具。

<a id="case-22"></a>

### 22 没有权限记录的旧会话按普通恢复

- **类型** 集成测试，实际 SQLite。
- **目的** 确认升级前会话沿用原有工具能力。
- **怎么测** 载入升级前创建且没有权限记录的会话库，通用默认设为只读。重新订阅旧会话，检查其权限为普通。

## 新会话首发

<a id="case-23"></a>

### 23 首发前手动选只读只影响该会话

- **类型** 端到端测试，Chromium、受控模型、实际服务。
- **目的** 检查网页在正式建会话前可以选择首轮权限。
- **怎么测** 通用默认值为普通。在新草稿输入内容后把权限改为只读，确认首发前侧栏未增加正式会话。点击发送，核对首轮请求只声明四个只读工具，正式会话显示只读。另开新草稿仍显示普通。

<a id="case-24"></a>

### 24 默认权限在另一页面改变后已打开草稿按原模式发送

- **类型** 端到端测试，两个 Chromium 页面、实际服务。
- **目的** 检查跨页面设置变化不会改变当前草稿的执行权限。
- **怎么测** 默认只读时在 A 页打开新草稿，在 B 页将默认改为普通。检查 A 的权限菜单仍是只读，首次点击发送即被接收并以只读调用模型。再新开一份草稿，检查显示普通。

<a id="case-25"></a>

### 25 首发写入失败时保留草稿与权限

- **类型** 集成测试（服务保存）及组件测试（Chromium，草稿反馈）。
- **目的** 验证首发保存的成败和页面行为一致。
- **怎么测** 准备内容为「查看 README」的只读草稿，使首发保存明确失败。后端没有正式会话和模型请求。页面保留原文与只读菜单，并提示保存失败。

<a id="case-26"></a>

### 26 首发回执丢失后以原权限重试仅运行一次

- **类型** 集成测试，实际 SQLite、服务重启和受控模型。
- **目的** 验证重试核对原提交的权限。
- **怎么测** 接收只读首发后丢弃回执，将通用默认值改为普通并重启。用相同提交编号、原文和只读权限重试，检查返回原回执，首发任务只有一份，模型没有再次执行。

<a id="case-27"></a>

### 27 首发编号相同但提交权限不同时拒绝

- **类型** 集成测试，实际 HTTP 和 SQLite。
- **目的** 防止首发重试被误用为权限变更。
- **怎么测** 提交只读首发并等待接收。保留原工作区、提交编号和原文，把权限改为普通后再次提交。检查请求被拒绝，原会话仍是只读，模型没有再次运行。

<a id="case-28"></a>

### 28 直接创建空会话时保存当时的默认权限

- **类型** 集成测试，实际 HTTP 和 SQLite。
- **目的** 覆盖已有的直接建会话入口。
- **怎么测** 将默认设为只读，经 `POST /api/sessions` 直接创建空会话。随后修改默认为普通，再打开此会话。检查仍是只读，发送第一条消息时使用只读。

## 通用设置

<a id="case-29"></a>

### 29 默认权限只影响未来的草稿和会话

- **类型** 端到端测试，Chromium、实际设置文件与服务重启。
- **目的** 检查通用设置的初始值、保存和新草稿初始化。
- **怎么测** 用未配置权限的设置文件启动，通用设置显示普通。保留一个普通会话，在通用设置改成只读。重启后通用设置仍是只读，后续打开的草稿显示只读，原会话仍是普通。

<a id="case-30"></a>

### 30 默认权限写入失败时显示已确认的值

- **类型** 组件测试，Chromium，受控 HTTP 响应。
- **目的** 检查失败不会显示成成功切换。
- **怎么测** 初始显示普通，选择只读后让保存请求失败，重读返回普通。检查下拉仍显示普通，且有失败提示。

<a id="case-31"></a>

### 31 默认权限回执丢失后按重读值显示

- **类型** 组件测试，Chromium，受控 HTTP 响应。
- **目的** 检查页面能从未确认的响应恢复。
- **怎么测** 选择只读，模拟服务已写入但断开保存响应。重新读取返回只读。检查下拉恢复成后端确认的只读。

<a id="case-32"></a>

### 32 非法权限值被拒绝

- **类型** 集成测试，实际 HTTP。
- **目的** 验证非法模式无法写入持久数据。
- **怎么测** 对默认权限保存接口提交 `"other"`。检查服务返回输入错误，重读仍得到原默认值。
