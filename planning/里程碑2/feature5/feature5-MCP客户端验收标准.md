## 配置和首次连接

<a id="case-01"></a>

### 01 保存带令牌的服务后保持未连接

- **类型**　集成测试
- **目的**　确认保存登记与网络连接分离。
- **怎么测**　记录受控 MCP 端点的请求。提交 GitHub 形式的名称、URL 和测试令牌，确认配置引用指向凭据文件，开关保持关闭，远端请求为零。查询只返回是否已配置，令牌只出现在本机凭据记录。

<a id="case-02"></a>

### 02 手动连接在工具查询完成后才就绪

- **类型**　浏览器组件测试与服务端集成测试
- **目的**　核对真实就绪条件和网页反馈。
- **怎么测**　打开已保存服务的开关。延迟工具列表，核对开关尚未开启。放行后核对协议请求和工具名，开关显示开启。工具列表查询失败时，开关回到关闭且不发布工具。

<a id="case-03"></a>

### 03 改名保留连接并更新工具名称

- **类型**　集成测试
- **目的**　确认展示名称变化不会触发断线。
- **怎么测**　连接后只修改名称。核对远端连接未替换，工具名按新名称更新，并保留启动恢复标记。

<a id="case-04"></a>

### 04 修改连接配置后等待再次手动连接

- **类型**　集成测试
- **目的**　确认旧客户端、凭据和工具退出。
- **怎么测**　将已连接服务更换 URL 并提交新测试令牌。核对旧客户端关闭，工具撤下，迟到结果不发布，新 URL 在重新打开开关前收到零请求。对更换授权方式、手填令牌及应用配置分别复用该检查。

<a id="case-05"></a>

### 05 凭据写入失败时保留原配置

- **类型**　集成测试
- **目的**　确认写入失败时现有服务可继续使用。
- **怎么测**　已有连接下替换手填令牌，注入凭据替换失败。核对配置引用、原凭据、运行连接和工具未切换，网页收到脱敏失败。

<a id="case-06"></a>

### 06 配置提交失败时保留原凭据引用

- **类型**　集成测试
- **目的**　确认新凭据单独写入时保持原服务可用。
- **怎么测**　替换令牌时允许新凭据写入，再使配置替换失败。核对原引用仍有效。分别在写完新凭据与切换配置之间模拟退出，重启仍使用原记录，无引用记录可清理。

<a id="case-07"></a>

### 07 提交成功后清理失败仍使用已提交配置

- **类型**　集成测试
- **目的**　确认清理错误不导致重复配置切换。
- **怎么测**　写入新配置成功后注入凭据清理或锁释放失败。核对读取结果采用已经提交的配置，显示可处理的诊断，下一次清理仍保留被引用的凭据。

## 启动恢复和服务管理

<a id="case-08"></a>

### 08 启动仅恢复当前配置手动连过且仍启用的服务

- **类型**　服务端集成测试
- **目的**　确认启动恢复条件和工具就绪顺序。
- **怎么测**　通过真实后端入口启动临时实例，预置符合条件、只保存、编辑后清除标记及停用的服务。只有符合条件的端点收到连接请求。延迟工具列表时核对开关尚未开启，列表返回后核对开关开启。

<a id="case-09"></a>

### 09 停用后两个会话都无法继续发送新调用

- **类型**　集成测试
- **目的**　确认停用由共享管理器执行。
- **怎么测**　两个会话取得同一个服务的工具定义，发起其中一次调用并暂缓回执。在设置停用服务，核对配置和凭据保留、工具撤下、两会话旧定义的后续调用均未发送。已经发出且未确认的调用按原编号保存为远端结果未知。

<a id="case-10"></a>

### 10 重新启用后由同一个管理器建立连接

- **类型**　集成测试
- **目的**　确认启用复用原凭据和服务登记。
- **怎么测**　启用一个停用服务，核对配置保存成功后新建一个共享客户端，工具发现前仍不可调用，发现后两个会话都可使用。

<a id="case-11"></a>

### 11 重连期间停用不会让迟到结果恢复工具

- **类型**　集成测试
- **目的**　确认最后保存的设置决定可用性。
- **怎么测**　重连时延迟新连接返回，在另一已授权页面停用。核对迟到的工具定义不发布，设置刷新后开关仍关闭。另用清理超时验证新连接不会抢先建立。

<a id="case-12"></a>

### 12 删除后重启不会再加载服务

- **类型**　服务端集成测试
- **目的**　确认登记的删除和凭据清理。
- **怎么测**　删除一个正在连接或等待 OAuth 的服务，确认条目、工具、等待均移除，凭据清理后重启无该服务。注入清理失败时核对删除仍生效、回执有清理提示，后续启动或保存可再清理。

<a id="case-13"></a>

### 13 停用保存失败时服务状态保持原样

- **类型**　集成测试
- **目的**　确认网络生命周期只跟随已提交配置。
- **怎么测**　在已连接服务停用时注入配置写入错误，核对原开关、连接及工具目录仍有效，页面显示失败。

## 浏览器 OAuth

<a id="case-14"></a>

### 14 OAuth 按配置及服务能力选择应用身份

- **类型**　协议单元测试
- **目的**　验证预设应用、既有登记、CIMD、DCR 的优先顺序。
- **怎么测**　用可控授权元数据分别覆盖四条分支，检查选中的 Client ID、登记请求次数和回调匹配。另检查身份文件和动态登记均不可用时返回可处理原因。

<a id="case-15"></a>

### 15 有效回调只兑换并保存一次后继续连接

- **类型**　浏览器与服务端集成测试
- **目的**　确认浏览器回调到令牌落盘的完整协作。
- **怎么测**　打开开关并等待浏览器打开授权页，让受控授权页重定向到本机。核对回调使用固定本机地址，身份、PKCE 与资源匹配，令牌仅存凭据文件，重复回调不兑换，并在工具发现后开启开关。授权页和更新事件不含令牌。

<a id="case-16"></a>

### 16 无效回调被拒绝且不能放宽普通 API 认证

- **类型**　服务端集成测试
- **目的**　确认回调例外只服务于当前授权。
- **怎么测**　分别发送错误或重复参数、签发者错误、错误回调路径及错误 Host。核对没有兑换和写入。再验证不带网页认证的普通 API 与 WebSocket 请求仍被拒绝。

<a id="case-17"></a>

### 17 取消授权后迟到回调失效

- **类型**　集成测试
- **目的**　确认授权等待可以安全取消。
- **怎么测**　启动授权后在设置拨回开关或取消，提交原回调，核对没有令牌写入或建连。用户拒绝、等待超时、停用或配置变更分别验证，各分支都不能发布旧结果。

<a id="case-18"></a>

### 18 令牌写入失败时授权可以重新发起

- **类型**　集成测试
- **目的**　确认未落盘的令牌不会用于连接。
- **怎么测**　让受控授权服务返回令牌，再注入凭据写入失败。检查原配置保留，状态可重试，无工具发布。重新授权使用新尝试和授权码。

<a id="case-19"></a>

### 19 授权成功后工具发现失败仍可重连

- **类型**　集成测试
- **目的**　确认授权与连接各自报告结果。
- **怎么测**　有效回调写入令牌后，让远端工具查询失败。设置的开关关闭。再次打开开关时复用已保存凭据，工具发现成功后才开启。

<a id="case-20"></a>

### 20 令牌刷新复用同一条凭据记录

- **类型**　集成测试
- **目的**　确认刷新成功和授权失效走相应路径。
- **怎么测**　让远端拒绝旧访问令牌，核对并发刷新共享一次请求，凭据更新后可继续连接。使刷新令牌失效时开关关闭，后台不打开浏览器。用户再次打开开关才发起交互授权。

## 调用、权限和连接恢复

<a id="case-21"></a>

### 21 普通模式读取远端工具结果并按原编号回填

- **类型**　集成测试
- **目的**　确认每轮声明与实际工具执行对应。
- **怎么测**　让受控模型选择已连接服务的工具。核对服务收到实际参数，工具卡、会话存储和下一轮模型上下文共用原调用编号。再次发消息时复用工具目录。

<a id="case-22"></a>

### 22 只读模式只提供四个内置读取工具

- **类型**　集成测试
- **目的**　确认远端只读提示不会更改权限。
- **怎么测**　启用返回只读标记的 MCP 工具，在只读会话验证模型声明只含 read、grep、find、ls。等待 Hook 时切换只读，核对实际发送前拦截，沿原编号回填。

<a id="case-23"></a>

### 23 远端明确报错后模型仍继续决策

- **类型**　集成测试
- **目的**　确认失败不关闭聊天会话。
- **怎么测**　受控工具返回明确的资源未找到错误，核对失败交给下一轮模型，连接恢复逻辑不会把此结果作为 MCP 会话过期。扩展补充说明后仍保留远端错误。

<a id="case-24"></a>

### 24 请求发出后失去响应时保留结果未知

- **类型**　集成测试
- **目的**　确认只有可证明未执行的调用才进入重试分支。
- **怎么测**　远端记录调用已收到后中断响应。等待故障回填后，核对旧调用只记录一次远端结果未知。单任务停止保留结果但不发起下一轮模型请求。

<a id="case-25"></a>

### 25 掉线后立即后台恢复，重试耗尽后关闭

- **类型**　集成测试
- **目的**　确认掉线保留工具入口和身份绑定。
- **怎么测**　在已连接服务上中断连接。核对用户未发新请求时已开始恢复，开关保持开启。两个会话共用同一次建连及工具发现，各自新请求只发一次，旧未知调用零重发。让恢复持续失败，核对最多尝试三次，之后开关关闭且工具撤下。

<a id="case-26"></a>

### 26 恢复后旧工具定义需要重新检查

- **类型**　集成测试
- **目的**　确认只使用恢复后有效工具。
- **怎么测**　让受控服务恢复后撤掉原工具或改变参数约束。原调用回填不可用或参数错误，远端不收到本次调用。恢复期间停用、改地址或单个会话取消分别验证，已失效的等待不发送。

<a id="case-27"></a>

### 27 明确的 MCP 会话过期最多重试原调用一次

- **类型**　集成测试
- **目的**　确认协议级恢复与新调用相区分。
- **怎么测**　已建立有会话的 Streamable HTTP 连接，远端对携带旧会话编号的请求返回协议规定的 404。核对新连接后重试一次，模型只收到原编号的一条结果。再次过期时不继续重试。

## 真实 GitHub 与 Notion

<a id="case-28"></a>

### 28 真实 GitHub 发现工具后开关开启

- **类型**　端到端测试，正式网页和真实 GitHub MCP
- **目的**　确认访问令牌走完整连接与工具发现链路。
- **怎么测**　在网页登记官方 GitHub 远程 MCP 的 Issues 只读地址并填写有效令牌。保存后确认开关关闭，再打开开关。核对真实协议连接记录、远端工具定义、开关开启及可用工具。

<a id="case-29"></a>

### 29 真实模型读取 GitHub Issue 的标题状态和链接

- **类型**　端到端测试，正式网页、真实模型和真实 GitHub MCP
- **目的**　确认 Agent 实际用 MCP 得到指定 Issue 的信息。
- **怎么测**　由验收者提供可访问的 Issue 链接，在普通模式发起读取。检查实际 issue_read 调用及结果，核对模型回复的标题、状态和链接与 GitHub 原页面一致。

<a id="case-30"></a>

### 30 真实 Notion 完成 OAuth 并读取指定页面

- **类型**　端到端测试，正式网页、真实浏览器授权、真实模型和 Notion MCP
- **目的**　确认用户授权与读取真实工作区页面的闭环。
- **怎么测**　保存 Notion 官方地址，打开开关并进入浏览器授权。用户选择有测试页面的工作区并同意。核对本机回调、凭据状态、工具发现和开关开启。再用真实模型读取指定页并核对标题和链接。

## 执行说明

现行实现的结果见[验收记录](./feature5-MCP客户端验收记录.md)。重新核对时，从开关发起连接和授权，确认卡片通过开关体现连接结果，三点菜单只包含编辑和删除。

独立复跑真实用例时需要可用的模型凭据、GitHub 令牌、可核对的 Issue、可访问的 Notion 工作区测试页面及用户完成浏览器授权。授权和工具链路一起通过后保存脱敏的调用和结果证据。记录 GitHub 与 Notion 同时启用时的工具声明占用，凭据和授权码保留在本机受保护流程中。 [项目校验命令](../../../docs/development.md#校验)
