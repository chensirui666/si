## 实现约定

- 单个附件上限为 50 MiB。未随消息发送的上传保留 24 小时，定期回收。已发送的文件随会话保留。
- 标题最多 40 个字符，后台请求有 8 秒超时。只有附件的首条消息以第一个附件名作临时标题。
- 计划模式限制模型调用的应用工具。本机扩展仍按现有信任边界运行。

未提交的本地文件预览保存在打开的页面中。附件或引用一旦提交，页面可在刷新后按原发送编号确认或重试。两个标签页使用同一扩展草稿时，如果另一页已先建立会话，当前页重新上传并绑定到新的草稿编号。

## 拖放、添加菜单和 Plan 开关补验

| 场景 | 实际结果 |
| --- | --- |
| 从桌面拖入 | 拖入时整页显示与 DSH 一致的半透明模糊背景和三卡插画，说明标出本项目的单文件 50 MiB 上限。移出页面或取消会收起提示。[3001 实际截图](evidence/拖入文件.png) Chromium 将临时目录中的真实文件拖到聊天页侧栏，文件只上传一次并进入当前草稿。混入目录会提示选择其中的文件。把普通选中文字拖到输入框会插入正文。[浏览器测试](../../../web/src/components/ChatFileDrop.browser.test.tsx) |
| 从添加菜单选择 | `+` 的「添加」分组有「添加文件」「计划模式」两项。「添加文件」打开系统文件选择器，选「计划模式」会把已有草稿放到 `/plan` 后面。两种入口的附件可以随首条计划任务一并发送。会话引用继续通过 `@` 选择。[端到端测试](../../../web/tests/e2e/plan-mode.spec.ts) |
| 任务运行中点 `Plan ×` | 同一次模型调用及其重试继续使用原来的工具权限。在端到端测试中，退出后，旧调用提出的写文件操作被拦截；同一任务的下一次调用成功写入临时工作区。只读会话退出后继续只读；未发出的下一条草稿得到保留。[端到端测试](../../../web/tests/e2e/plan-mode.spec.ts) · [调用和权限测试](../../../packages/coding-agent/test/plan-mode.test.ts) |
| 在待审方案上退出 | 网页只提交 `/plan off`。服务端关闭评审并保留方案原文；刷新后仍可查看，没有新增执行轮。点击「确认执行」走独立的评审接口。[端到端测试](../../../web/tests/e2e/plan-mode.spec.ts) |
| 真实模型读取拖入的文件 | Chromium 将本地日志文件拖入网页。DeepSeek Flash 发起 `read`，读出仅存在于文件内的随机故障码 `AGL-AC19AA67`，最终回复包含该故障码。截图粘贴回归也通过，首轮直接读出 `57F9E58A`、`5CE0D87F`、`6CA74378`。[真实模型测试](../../../web/tests/e2e/chat-attachments.live.spec.ts) |
