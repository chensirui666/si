# Feature1 视觉改造记录

依据：用户提供的布局截图、指定的 `design.md`，以及补充确认的发送按钮状态。改动位于现有 `codex/feature1-chat` worktree；主目录的设计规范及其他未提交修改未改动。

## 实现

- 白色页面，760px 居中内容列，消息区和输入区同轴；窄屏左右至少 16px。
- 近黑主文字和操作、浅灰用户气泡；用户原文展示方式不变。
- 正文、输入为 14/24、400，标题为 20/28、600；本地 Noto Sans CJK SC 实际用于渲染。
- 发送按钮为向上箭头，保留名称“发送”。空稿/全白稿为 `#F7F7F5` 背景与 `#707070` 图标、禁止操作；有效稿为 `#1A1A1A` 背景与白色图标。状态立即切换；悬停为 `#333333`。
- 消息与输入框均按规范使用圆角和内边距；输入框使用固定轻微阴影，聚焦保持弱边界；消息区和按钮以局部小点提示焦点，不画整圈轮廓。
- 输入框随草稿自然增高，达到上限后内部滚动。发送清空后缩回；输入增长与清空不改变旧消息阅读位置。
- 桌面发送按钮 36px；窄屏和主指针为触摸的设备至少 44×44px。低高度视口收紧纵向间距，为编辑区与发送操作保留空间。
- 正文、代码、设计字三个字体资源及 OFL 许可随应用提供，详见 `web/public/fonts/README.md`。当前页面没有新增品牌或欢迎标题，因此中文标题使用正文家族；EB Garamond 不强行用于中文。

核心提交、输入法、撤销与原文读取逻辑未改变；`MessageInput.tsx` 仅调整显示标记、可访问名称及快捷键提示文案。

## 2026-10-28 聚焦视觉校正

用户确认输入区和消息滚动区不应因聚焦出现明显边框变化，按钮以背景反馈交互。此前输入框同时画 1px 边框和外移 2px 的 2px 轮廓，且编辑区鼠标聚焦也匹配 `:focus-visible`，形成双框；现已移除这两条聚焦规则。

- 输入框边界恒定为 1px `#DEDEDB`，输入位置由光标标示；聚焦、Tab 切换和发送清空均不改变边界或布局。
- 消息滚动区不画框，保留 Tab 与 PageDown 等原生键盘操作。外壳只负责在左上角固定一个 6px 焦点小点，不参与消息排版、不跟随内容滚动。
- 公共 Button 移除默认焦点光圈；需要焦点提示时，内部显示 4px 小点。浅色按钮悬停 `#F0F0EE`、按下 `#DEDEDB`；黑色发送按钮悬停 `#333333`、按下 `#1A1A1A`。高对比度模式使用系统文字色显示小点。
- CT 将 Vite 根目录设为 `web/playwright`，此前生成的组件测试 CSS 缺少公共按钮工具类；新增 `@source "./"` 明确扫描 `web/src`，与正常构建共享组件样式。依据：[Tailwind 官方源码扫描说明](https://tailwindcss.com/docs/detecting-classes-in-source-files#explicitly-registering-sources)。

Pi 参考仍是编辑状态与焦点呈现分开：`pi/packages/tui/src/tui.ts` 的 `Focusable` 和 `pi/packages/tui/src/components/editor.ts` 的光标标记。Pi 为终端实现，本次未将它视为 Web 样式规范；没有改变 Lexical、发送、输入法或撤销逻辑，没有新增依赖。

## 2026-10-28 页面文案与输入框阴影调整

- 移除输入区常驻的“Enter 发送 · Shift+Enter 换行”提示；Enter 发送、Shift+Enter 换行及输入法保护行为保持不变。
- 移除标题右侧的“本地”标识，标题只保留“聊天”。
- 输入框增加轻微阴影 `0 2px 12px 0 rgba(0, 0, 0, 0.04)`，常态和聚焦保持一致，不将阴影用作焦点光圈；边界仍恒定、不加粗。此为输入框例外，浮层原有阴影规则保留。

验证：阴影断言先在旧实现上失败（实际为 `none`）；修改后 `npm test` 的 DOM 20/20、Chromium 组件 17/17，E2E 1/1 及构建均通过。当前 5173 页面实测标题仅为“聊天”、快捷键提示已消失、阴影值正确，发送按钮仍距输入框右边缘 17px；常态与聚焦的阴影由同一条规则负责。`git diff --check` 通过。本次没有重跑系统中文输入法验收。
