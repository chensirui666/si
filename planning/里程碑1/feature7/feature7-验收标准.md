<a id="scope"></a>

## 1. 压缩范围与摘要内容

验证压缩能够选取合适的较早内容，在保持工具调用与结果配对、按约定处理长结果的基础上，生成可供后续任务使用并可再次更新的摘要。

<a id="case-01"></a>

### 01 无可压缩内容时不执行压缩

- **类型：** 单元测试。
- **目的：** 保留预算已覆盖全部原文时，避免无意义摘要调用。
- **怎么测：** 构造估算合计低于 20,000 的已完成对话，调用准备函数；检查返回无候选、输入未修改，Agent 不调用摘要流。

<a id="case-02"></a>

### 02 刚压缩且无新内容时不重复压缩

- **类型：** 单元测试。
- **目的：** 避免把状态更新当成新消息。
- **怎么测：** 成功记录对应当前最后有效原文，随后仅更新运行/容量状态，再准备压缩；检查已压缩原因且无摘要调用。

<a id="case-03"></a>

### 03 压缩时工具调用与对应结果不被拆开

- **类型：** 单元测试。
- **目的：** 防止压缩后出现孤立工具结果。
- **怎么测：** 构造助手同时请求 read、grep，结果跨过近期预算；检查调用与两项结果一起保留或一起进入候选，边界不从结果开始。当前长任务的早期轮次可进入候选。

<a id="case-04"></a>

### 04 长工具结果仅取前 1,500 和后 500 字符用于摘要

- **类型：** 单元测试。
- **目的：** 保留用户指定的头尾预算并明确省略部分。
- **怎么测：** 构造 3,000 字符的工具结果，头部含“项目青禾”、中部含“中段”、尾部含“退出码 0”，截取边缘带有 emoji；检查摘要输入保留前 1,500/后 500 个完整字符及截断提示，中部被省略，原始记录不变。

<a id="case-05"></a>

### 05 短工具结果完整进入摘要输入

- **类型：** 单元测试。
- **目的：** 避免对无需截取的结果改写内容。
- **怎么测：** 将“项目青禾，退出码 0”交给摘要序列化，检查与原文逐字符一致，没有截断提示。

<a id="case-06"></a>

### 06 工具结果恰好 2,000 字符时保持完整

- **类型：** 单元测试。
- **目的：** 明确截取预算的边界。
- **怎么测：** 序列化恰好 2,000 个字符的结果，检查完整保留且没有重复片段或截断提示。

<a id="case-07"></a>

### 07 再次压缩时合并旧摘要与新内容

- **类型：** 单元测试。
- **目的：** 避免重放已替代原文或堆叠历次摘要。
- **怎么测：** 上次摘要含“项目名青禾”，其后原文把输出格式从 Markdown 更正为 JSON；检查第二次摘要输入包含旧摘要与新候选，排除已替代原文，后续模型输入只含最新摘要与近期原文。

<a id="input-and-usage"></a>

## 2. 模型输入、错误识别与用量

验证压缩只改变消息历史而保留正常任务的系统提示词，并按实际输入估算占用、区分不同错误及如实记录对应摘要的用量。

<a id="case-08"></a>

### 08 压缩成功后正常任务的系统提示词保持原样

- **类型：** Agent 单元测试。
- **目的：** 确保压缩只改变消息历史，摘要调用的整理指令不会覆盖任务系统提示词。
- **怎么测：** 在固定临时工作区构造足够历史，先执行“读取 index.txt”并保存普通请求的完整 systemPrompt；手动压缩成功后提交“继续”，逐字比较新普通请求的 systemPrompt，检查与原值完全一致、工具定义未改，而 messages 已切换为摘要与近期原文；摘要调用可使用独立整理指令，但它不能出现在后续任务的系统位置。

<a id="case-09"></a>

### 09 带工具请求的全部有效内容都纳入估算

- **类型：** 单元测试及受控 SDK 集成测试。
- **目的：** 防止漏掉系统、工具声明、调用结果或适用历史思考。
- **怎么测：** 准备系统提示“只操作当前目录”、read 定义，以及含思考、read 调用和“项目青禾”结果的 ModelContext；检查实际请求与估算均包含这些内容，工具定义与调用结果分属不同类别，模型和输出预算正确。复用原有消息转换和配对覆盖。

<a id="case-10"></a>

### 10 不带工具时不将历史思考计入输入

- **类型：** 单元测试及受控 SDK 集成测试。
- **目的：** 防止服务商忽略的历史思考被计为有效输入。
- **怎么测：** 准备助手正文“项目青禾”及历史思考“先读取目录”，不提供工具；检查请求转换与估算均按无工具规则处理历史思考，正文仍保留。

<a id="case-11"></a>

### 11 明确超限时识别错误并隐藏敏感内容

- **类型：** 受控 SDK 集成测试。
- **目的：** 避免重试普通错误及泄露原始正文。
- **怎么测：** 服务替身返回明确上下文超限错误，正文中加入测试凭据标记；检查只调用一次、返回安全超限分类，公开信息不含原始正文或凭据标记。

<a id="case-12"></a>

### 12 参数错误时不触发超限恢复

- **类型：** 受控 SDK 集成测试。
- **目的：** 避免参数错误触发压缩恢复。
- **怎么测：** 返回普通无效参数 400，检查没有超限分类且不自动重试，错误脱敏行为保持。

<a id="case-13"></a>

### 13 认证失败时不触发超限恢复

- **类型：** 受控 SDK 集成测试。
- **目的：** 避免无效凭据触发压缩恢复。
- **怎么测：** 返回 401，检查没有超限分类且不自动重试，不公开测试凭据。

<a id="case-14"></a>

### 14 遭遇限流时不触发超限恢复

- **类型：** 受控 SDK 集成测试。
- **目的：** 避免限流时额外生成摘要。
- **怎么测：** 返回 429，检查没有超限分类且不自动重试，保留原有限流错误处理。

<a id="case-15"></a>

### 15 网络失败时不触发超限恢复

- **类型：** 受控 SDK 集成测试。
- **目的：** 防止网络异常进入上下文恢复。
- **怎么测：** 让 fetch 抛出连接错误，检查没有超限分类且只调用一次。

<a id="case-16"></a>

### 16 未报告输入用量时保持未知

- **类型：** 已有集成测试回归。
- **目的：** 保持真实用量的来源。
- **怎么测：** 复跑 `model-stream.test.ts` 的缺失与部分字段案例，检查只有 output 或 total 时仍没有伪造 input。

<a id="case-17"></a>

### 17 后续真实输入用量关联到实际使用的摘要

- **类型：** 单元测试。
- **目的：** 避免摘要调用或新摘要用量污染旧记录。
- **怎么测：** 准备两条成功压缩记录及对应请求编号，让任务输入用量先缺失后报告，检查只有实际使用对应摘要的首个有效任务用量建立引用；摘要消耗单列，之后请求不覆盖首次记录。

<a id="execution-and-protection"></a>

## 3. 手动、自动压缩与异常保护

验证手动和自动压缩能够正确触发并衔接任务，在失败、中止或超限时保护旧上下文，避免无限恢复和重复执行工具。

<a id="case-18"></a>

### 18 提交压缩命令后只执行压缩，不新增聊天消息

- **类型：** 单元测试。
- **目的：** 确保 `/compact` 的接收和执行行为正确。
- **怎么测：** 构造足够历史后提交 `/compact`，检查分类回执、独立运行、后台摘要、成功记录与新有效输入，原始消息不变。

<a id="case-19"></a>

### 19 通过正式接口可接收并中止压缩命令

- **类型：** HTTP/WS 集成测试。
- **目的：** 确保后端识别及中止协议对所有调用方一致。
- **怎么测：** 经授权 HTTP 提交 `/compact`，检查 202 回执与订阅记录对应，普通用户消息未追加；再以 runId 中止并核对收尾。沿用原来源、Cookie、媒体类型、大小、工作区和错误回归。

<a id="case-20"></a>

### 20 任务运行期间拒绝手动压缩

- **类型：** 单元测试。
- **目的：** 避免手动压缩打断正在执行的任务。
- **怎么测：** 保持一次 read 任务运行，再提交 `/compact`；检查明确拒绝，没有新压缩记录，原任务继续。

<a id="case-21"></a>

### 21 工具批次结束且达到阈值时自动压缩并继续任务

- **类型：** 单元测试。
- **目的：** 覆盖新工具结果增长与连续任务。
- **怎么测：** 使用两项完成时间不同的真实执行替身，结果使预计输入越过测试阈值；检查整批收齐后才压缩，成功后同一任务继续调用模型，模型、工作区、工具与先前执行次数保持正确。复用 Feature6 的连续决策与乱序结果检查。

<a id="case-22"></a>

### 22 自动压缩失败但原输入仍放得下时继续任务

- **类型：** 单元测试。
- **目的：** 验证已确认的失败后继续规则。
- **怎么测：** 让输入越过提前阈值但未超过输入与回复预算的容量，摘要请求报错；检查保留原有效上下文、失败记录可见且普通任务继续，只尝试一次阈值压缩。

<a id="case-23"></a>

### 23 摘要被截断时保留旧上下文

- **类型：** 单元测试。
- **目的：** 防止未完成或无效摘要取代真实历史。
- **怎么测：** 摘要请求以 length 结束，检查保留原有效上下文和边界，记录失败，不将部分正文提交为摘要。

<a id="case-24"></a>

### 24 摘要为空时保留旧上下文

- **类型：** 单元测试。
- **目的：** 避免空结果丢失上下文。
- **怎么测：** 摘要请求正常结束但正文为空，检查压缩失败，原摘要和保留边界不变。

<a id="case-25"></a>

### 25 摘要带工具调用时拒绝摘要且不执行工具

- **类型：** 单元测试。
- **目的：** 防止独立摘要产生工具副作用。
- **怎么测：** 摘要响应意外带有 write 调用，检查不执行该工具、不提交摘要，原有效上下文不变。

<a id="case-26"></a>

### 26 压缩未缩短输入时保留旧上下文

- **类型：** 单元测试。
- **目的：** 防止无效整理被记为成功。
- **怎么测：** 摘要完整但重新估算后的任务输入不小于原输入，检查失败记录和旧边界，没有成功切换。

<a id="case-27"></a>

### 27 压缩后仍超容量时不提交摘要并停止任务

- **类型：** 单元测试。
- **目的：** 避免提交不能继续任务的压缩结果。
- **怎么测：** 构造近期原文很大、摘要虽缩短但完整输入与回复预算仍超过容量的任务，检查不提交新边界、不再请求模型，原始记录保留。

<a id="case-28"></a>

### 28 自动压缩失败且原输入超容量时停止任务

- **类型：** 单元测试。
- **目的：** 避免继续发送预计必定超限的原输入。
- **怎么测：** 原输入与回复预算已超过容量，摘要请求报错；检查保留原有效上下文并结束任务，不发送原请求。

<a id="case-29"></a>

### 29 中止压缩后等待收尾，不再继续请求

- **类型：** 单元测试。
- **目的：** 防止取消后继续请求或过早恢复发送。
- **怎么测：** 摘要流收到取消后延迟清理，检查等待期间仍忙碌、旧编号不影响新任务、收尾前不提交摘要或启动下一次模型调用；复用 Feature5 重复中止和成功竞态覆盖。

<a id="case-30"></a>

### 30 超限重试仍失败时停止且不重跑工具

- **类型：** 单元测试。
- **目的：** 防止无限恢复和重复工具副作用。
- **怎么测：** 先完成向 note.txt 写入“青禾”，下一轮明确超限，压缩后重试仍超限；检查只恢复一次、写入不重跑、原始结果保留并结束。

<a id="case-31"></a>

### 31 超限且无可压缩内容时直接停止任务

- **类型：** 单元测试。
- **目的：** 避免重复发送已拒绝的原输入。
- **怎么测：** 保留范围已覆盖全部原文，普通请求明确超限；检查无摘要请求，也不重发原输入，任务结束。

<a id="case-32"></a>

### 32 超限恢复中的摘要失败时停止任务

- **类型：** 单元测试。
- **目的：** 避免用旧上下文反复恢复。
- **怎么测：** 普通请求明确超限，随后摘要请求报错；检查旧上下文保留，没有重发原输入，任务结束。

<a id="case-33"></a>

### 33 恢复成功后的新请求再次超限时可再恢复一次

- **类型：** 单元测试。
- **目的：** 防止把“当前连续失败请求一次”误实现为“整个任务一次”。
- **怎么测：** 首次超限后压缩并重试成功，执行一次 read 得到新结果；下一轮请求再次明确超限，检查允许针对这个新请求再恢复一次，成功后继续任务，先前工具均没有重跑。

## 4. 刷新与重连

验证页面断线后后台压缩仍能继续，并在重连时完整恢复实际状态与长历史，即使连接较慢也不重复执行任务。

<a id="case-34"></a>

### 34 压缩中断线后重连可恢复成功结果

- **类型：** HTTP/WS 集成测试。
- **目的：** 证明连接生命周期不重启或取消后台任务。
- **怎么测：** 在摘要运行时断开 WS，后台继续到成功，再订阅检查原任务只运行一次、原始历史和压缩结果恢复。复跑已有快照、跳号、重复序号和订阅清理覆盖。

<a id="case-35"></a>

### 35 断线期间压缩失败时重连可查看失败结果

- **类型：** HTTP/WS 集成测试。
- **目的：** 避免重连补跑已失败操作。
- **怎么测：** 断开正在压缩的页面，令摘要请求失败，再订阅；检查失败记录和旧有效上下文恢复，摘要调用次数仍为一。

<a id="case-36"></a>

### 36 压缩中止后重连仍显示已停止

- **类型：** HTTP/WS 集成测试。
- **目的：** 防止中止后的操作在重连时复活。
- **怎么测：** 中止一次摘要并等待收尾，再断开和重新订阅；检查空闲、已停止记录和原始历史恢复，没有新模型调用。

<a id="case-37"></a>

### 37 压缩成功时建立订阅仍能取得完整状态

- **类型：** HTTP/WS 集成测试。
- **目的：** 验证摘要、边界与记录的一致交接。
- **怎么测：** 摘要返回完成时建立新订阅，控制快照复制与成功发布的先后；检查最终取得完整成功记录及匹配边界，序号连续且没有重复记录。

<a id="case-38"></a>

### 38 长历史恢复时完整接收快照与后续更新

- **类型：** HTTP/WS 集成测试。
- **目的：** 防止正常长会话陷入恢复循环。
- **怎么测：** 在隔离 Agent 状态准备 3 MiB 原始文本及有效压缩记录，订阅发送完整快照的同时产生后续更新，检查客户端收到可用快照并追平序号。未通过前不宣称长历史恢复达标。

<a id="case-39"></a>

### 39 慢连接断开后后台压缩继续完成

- **类型：** HTTP/WS 集成测试。
- **目的：** 保留慢连接保护且不误停任务。
- **怎么测：** 让订阅端停止读取并积压到现有保护阈值，检查连接被清理、Agent 摘要继续完成；新连接能取得最终记录。
