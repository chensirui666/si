# Feature1 实施计划

**目标：** 按 [Feature1 技术设计](./feature1-基本聊天页面.md) 实现本地输入、发送、展示，并逐项记录八组验收的真实结果。

**结构：** `App → ChatPage → MessageInput / MessageList`。Lexical 持有草稿；ChatPage 持有用户消息。沿用 React、TypeScript、Vite、Tailwind CSS 与 shadcn/ui，不建立 Agent 核心或后端。

## 约束与检查重点

- 只完成里程碑第一步；不调用模型、不生成模拟回复、不持久化。
- 同步 `onSend(text): boolean`，只有接收成功才清空草稿和历史。
- 原文空格、段落、连续空行、末尾换行、最后输入的文字都保留。
- 输入法确认、修饰键和重复 Enter 不发送；普通 Enter 发送，Shift+Enter 换行。
- 消息列表独立滚动；输入区高度稳定；发送和恢复焦点不改变阅读位置。
- Pi 提供运行与界面分开的原则。dsh 的跟随底部、Ctrl/Cmd+Enter 发送与本文不同，按本文实现。
- 自动化模拟输入法事件不能证明真实选字或实际 Safari 已通过。
