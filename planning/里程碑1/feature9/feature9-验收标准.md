## 1. 说明发现

<a id="case-01"></a>

### 01 同一目录选中优先级最高的可读说明

- **类型** 单元测试，使用临时文件夹。
- **目的** 验证同级候选择一和文件名优先级。
- **怎么测** 在同一目录为五种候选准备不同正文，从 `AGENTS.override.md` 开始逐个移走，每次重新读取并核对只返回顺位最高的一份。完整大小写顺序在区分文件名大小写的文件系统上运行。大小写不敏感的环境至少验证 `AGENTS.override.md`、`AGENTS.md`、`CLAUDE.md` 三个可区分名称。

<a id="case-02"></a>

### 02 首选候选是目录时使用下一候选

- **类型** 单元测试，使用临时文件夹。
- **目的** 验证普通文件校验。
- **怎么测** 创建名为 `AGENTS.override.md` 的目录和内容为 `运行 npm test` 的普通文件 `AGENTS.md`。加载后检查仅返回 `AGENTS.md` 及其正文。

<a id="case-03"></a>

### 03 首选候选读取失败时记录原因并继续查找

- **类型** 单元测试，模拟文件读取返回 `EACCES`。
- **目的** 验证文件存在但读不到时可以回退，诊断只包含路径和原因。
- **怎么测** 让 `AGENTS.override.md` 打开时返回 `EACCES`，`AGENTS.md` 内容为 `先阅读 README.md`。核对记录指向首选候选并标明读取原因，返回的说明是 `AGENTS.md`。

<a id="case-04"></a>

### 04 符号链接指向普通文件时加载目标内容

- **类型** 单元测试，使用真实符号链接。
- **目的** 验证选中的链接沿用 Pi 的读取行为和来源标记。
- **怎么测** 让工作区 `AGENTS.md` 指向另一临时目录的 `shared.md`，正文为 `使用 pnpm 检查`。核对返回的来源为工作区 `AGENTS.md`，正文来自 `shared.md`。

<a id="case-05"></a>

### 05 没有说明时普通请求照常发出

- **类型** 集成测试，使用受控文件系统和模型端。
- **目的** 验证缺少说明是合法状态。
- **怎么测** 让全局目录和工作区祖先链均无候选文件，发出「你好」。核对请求包含已有系统提示词、工作目录、工具定义和用户原文，项目说明段未出现，WebSocket 收到正常回复事件。

<a id="case-06"></a>

### 06 全局与各级祖先说明按范围排列

- **类型** 单元测试，使用受控路径树。
- **目的** 验证祖先搜索包含 `/`，返回顺序符合 Pi。
- **怎么测** 在模拟的全局目录、`/`、`/home/person`、`/home/person/project` 和工作区 `/home/person/project/src` 放不同说明，在工作区的下级目录及另一个项目也放说明。核对结果按全局、根、用户目录、项目目录、工作区排列。下级目录和另一个项目的说明没有被收录。

<a id="case-07"></a>

### 07 嵌套 Git 工作树的说明遮蔽主工作区同名说明

- **类型** 单元测试，使用临时 Git 工作树布局。
- **目的** 验证同一仓库作用范围的说明只应用一次。
- **怎么测** 在主工作区与其下的链接工作树分别放 `AGENTS.md`，在主工作区上一层再放一份说明。从链接工作树的子目录加载，核对保留工作树说明和上一层说明，主工作区的同名正文未被收录。

## 2. 逐轮使用与隔离

<a id="case-08"></a>

### 08 首次发送使用最终选中的工作区

- **类型** 集成测试，复用正式首发接口和受控模型端。
- **目的** 验证文件读取绑定正式提交选择的工作区。
- **怎么测** 准备互为同级的 A、B 工作区，各有独立说明。在正式首发接口传入最终选择的 B 编号。检查会话登记在 B，出站请求仅含 B 的说明。再向 A 的已有会话发送，检查对应请求仅含 A 的说明。网页草稿中的目录切换由 Feature 8 的已有覆盖验证。

<a id="case-09"></a>

### 09 多轮模型请求各自携带一份当前说明

- **类型** 集成测试，使用受控模型端。
- **目的** 验证同一说明随请求使用且不会累积进聊天历史。
- **怎么测** 写入含唯一标记 `project-rule-09` 的说明，连续发起十次普通模型调用。检查每次请求的首条系统消息都恰有一份该标记，后续历史消息和网页会话快照都未新增说明消息。

<a id="case-10"></a>

### 10 工具改写说明后下一轮使用新版

- **类型** 集成测试，使用真实本地 `edit` 工具与受控模型端。
- **目的** 验证同一任务的工具续轮会刷新说明。
- **怎么测** 首轮检查系统提示词含 `旧约定`，让受控模型请求 `edit`，把说明改为 `新约定`。核对工具确实写入并返回结果，第二轮系统提示词含 `新约定`，旧版已被替换。

<a id="case-11"></a>

### 11 外部改写说明后下一条任务使用新版

- **类型** 集成测试，使用真实临时文件与受控模型端。
- **目的** 验证文件由用户或另一个进程修改时，已有会话仍能自动更新。
- **怎么测** 首条任务完成后在测试进程把 `AGENTS.md` 从 `使用 npm` 改为 `使用 pnpm`，在同一会话发下一条普通任务。检查请求仍带自己的聊天历史，系统提示词使用 `使用 pnpm`。

<a id="case-12"></a>

### 12 新增优先候选后下一轮改用新文件

- **类型** 集成测试，使用临时文件与受控模型端。
- **目的** 验证逐轮检查会发现新文件，而非仅检查此前已加载的路径。
- **怎么测** 首轮仅有 `AGENTS.md`。再新增内容不同的 `AGENTS.override.md` 后发下一条任务，检查同一目录仅使用 `AGENTS.override.md`。

<a id="case-13"></a>

### 13 删除优先候选后下一轮回退

- **类型** 集成测试，使用临时文件与受控模型端。
- **目的** 验证已删除的说明从后续系统提示词中移除。
- **怎么测** 首轮同时有 `AGENTS.override.md` 和 `AGENTS.md`，首轮选中前者。删除前者再发下一条任务，检查只包含 `AGENTS.md`，未沿用已删除的正文。

<a id="case-14"></a>

### 14 同工作区的两段会话共用说明且历史独立

- **类型** 集成测试，复用会话隔离的现有入口。
- **目的** 验证共享文件时聊天依然各自归属。
- **怎么测** 在同一工作区新建 A、B 两段会话，各发不同的任务标记并各自续聊。检查两个请求都带同一份项目说明，历史只包含对应会话的任务标记。

## 3. 压缩、容量与中止

<a id="case-15"></a>

### 15 手动压缩只整理聊天且下一条任务仍携带说明

- **类型** 集成测试，扩充已有手动压缩请求检查。
- **目的** 验证项目说明独立于压缩的历史。
- **怎么测** 准备足够长的聊天历史和含唯一标记的说明，发送 `/compact`。检查摘要请求有独立的摘要提示词且未带项目说明段。发送「继续」，检查普通请求同时包含该说明、新摘要和保留的近期聊天，页面仍可看原始历史。

<a id="case-16"></a>

### 16 自动压缩后的普通请求同时携带说明与新摘要

- **类型** 集成测试，扩充已有自动压缩用例。
- **目的** 验证项目说明参与普通请求容量估算。
- **怎么测** 调低测试压缩阈值，准备加入项目说明后才超过该阈值的历史。发送任务，检查先收到摘要请求。摘要成功后，检查普通请求带完整说明和新摘要，容量统计把说明计入系统提示词。

<a id="case-17"></a>

### 17 模型报容量超限后恢复请求重新检查说明

- **类型** 集成测试，扩充已有超限恢复用例。
- **目的** 验证恢复时使用当前说明，已经完成的工具操作只执行一次。
- **怎么测** 让一个任务先完成工具操作，再由受控模型对普通请求报告容量超限。生成摘要期间修改说明。检查恢复只重试当前请求一次，重试携带新版说明和摘要，已有工具结果仍在且工具未重跑。

<a id="case-18"></a>

### 18 说明自身超限时提示精简并保留工具结果

- **类型** 集成测试，使用临时大文件与受控模型端。
- **目的** 验证说明无法放入模型容量时能够明确结束任务。
- **怎么测** 让任务已有一条成功的工具结果，然后在下一轮准备前把说明改成单独就超过该模型容量的文本。检查该轮未发出普通请求，网页获得精简说明的任务错误，原消息和成功工具结果仍可查看。

<a id="case-19"></a>

### 19 中止说明准备后不会发出本轮请求

- **类型** 集成测试，控制说明读取的完成时机。
- **目的** 验证取消在读取与模型调用之间也能生效。
- **怎么测** 暂缓一轮说明读取，等会话进入运行状态后中止。释放读取并检查文件已收尾关闭、没有发出该轮模型请求、会话回到空闲且保留已有聊天。再发一条任务，核对会话可继续。

## 4. 真实模型使用

<a id="case-20"></a>

### 20 真实模型使用项目说明完成首发任务

- **类型** 端到端测试，Chromium、本地服务和真实 DeepSeek。
- **目的** 验证同一条链路从网页首发，到项目文件进入实际出站请求，再到模型使用信息并显示结果。受控模型端只能验证输入形状。
- **怎么测** 在临时工作区的说明文件独立写入随机项目标记，用户只发「按项目说明回答项目标记」。用现有请求记录入口检查首个出站请求的系统消息包含该标记，用户原文未提供该标记。等待真实回复，检查网页收到正确标记且没有依赖模型额外用工具读取该文件。
