## 提交与接收

<a id="case-01"></a>

### 01 首条消息写入后才确认接收

- **类型** 服务集成测试。
- **目的** 验证首发登记与消息、任务一起提交。
- **怎么测** 用测试工作区首发「读取 README.md」。暂缓存储提交，检查没有成功回执、正式会话或模型调用。允许提交后，检查同一会话的摘要、原文和任务开始记录都已保存，再收到接收回执并启动模型。

<a id="case-02"></a>

### 02 首条消息保存失败时保留草稿并提示

- **类型** 组件测试（Chromium）。
- **目的** 验证已知首发失败的页面反馈。
- **怎么测** 让服务明确返回首发保存失败。在新会话输入「读取 README.md」并发送。检查原文留在草稿、侧栏没有正式会话，顶部出现提示，计时 3 秒后消失。

<a id="case-03"></a>

### 03 已有会话的消息保存失败时不启动任务

- **类型** 服务集成测试。
- **目的** 验证已有会话收到明确保存拒绝。
- **怎么测** 在已有会话提交第二条消息，模拟 SQLite 确认回滚。检查接口明确返回未接收，已有消息完整，无新用户消息、任务记录或模型请求。

<a id="case-04"></a>

### 04 首发回执丢失后用原编号找回同一任务

- **类型** 服务集成测试。
- **目的** 验证重试不会创建或执行两次。
- **怎么测** 写入首发后丢弃回执，重启服务，用原工作区、模型、原文和提交编号重试。检查返回原会话和任务，库中只有一份首发记录，模型调用总数不增加。再用同编号提交不同原文，检查明确拒绝。

<a id="case-05"></a>

### 05 独立新建的会话重启后仍在原工作区

- **类型** 服务集成测试。
- **目的** 验证已有独立新建接口也登记到磁盘。
- **怎么测** 通过 POST /api/sessions 在已登记的目录建空会话，重启服务后查询侧栏接口。检查原编号、名称及工作区一致，打开时返回空的已保存历史。

## 模型回复与工具结果

<a id="case-06"></a>

### 06 工具调用写入失败时整批零执行

- **类型** 服务集成测试。
- **目的** 验证先保存调用再允许工具执行。
- **怎么测** 让模型返回修改 README.md 的调用，并在写入该回复时触发保存失败。检查工具调用次数为零、文件内容一致，任务结束并提示本批工具未执行。

<a id="case-07"></a>

### 07 串行工具结果写入失败时停止后续工具

- **类型** 服务集成测试。
- **目的** 验证串行的执行与写入顺序。
- **怎么测** 串行执行 A、B、C。让 A 的结果保存成功，让 B 修改测试文件后返回，再让 B 的结果写入失败。检查 A 保留、B 的实际改动保留、C 未启动，且模型没有下一次请求。

<a id="case-08"></a>

### 08 并行工具整批收尾后按调用顺序保存

- **类型** 服务集成测试。
- **目的** 验证写入与完成通知以调用顺序为准。
- **怎么测** 并行发起 A、B、C，控制 C 先返回。其余工具尚未收尾时检查结果表没有本批结果，网页没有 C 的完成通知。放行 A、B 后核对结果和完成通知顺序均为 A、B、C。

<a id="case-09"></a>

### 09 并行写到 B 失败时保留 A 且不发布 C

- **类型** 服务集成测试。
- **目的** 验证并行部分保存失败保留已提交记录。
- **怎么测** 让 A、B、C 全部执行并返回，控制 A 写入成功、B 写入失败。检查 SQLite 只有 A 的结果，C 未收到完成通知，本轮失败且没有下一次模型请求。

<a id="case-10"></a>

### 10 工具自身报错且结果已保存时模型仍可继续

- **类型** 服务集成测试。
- **目的** 区分工具执行失败与存储失败。
- **怎么测** 让读取工具返回「文件不存在」，并正常保存这条错误结果。核对下一次模型请求携带对应错误，工具卡片可展开查看失败原因。

<a id="case-11"></a>

### 11 纯文字回答首次写入失败后在收尾保存

- **类型** 服务集成测试。
- **目的** 验证暂时写入失败能在收尾恢复。
- **怎么测** 让模型生成「启动命令已核对」，第一次保存时注入临时失败，收尾时允许保存。检查正文只保存一次，终态为完成，刷新可读原文。

<a id="case-12"></a>

### 12 纯文字回答收尾仍未保存时保留已显示文字

- **类型** 组件与服务集成测试。
- **目的** 验证保存失败提示与回答正文可以同时显示。
- **怎么测** 让文字已流式显示，首次写入和收尾保存均失败。检查网页保留已显示的文字，在本轮末尾提示「回答已生成，但未保存」，任务终态未被写成成功。

<a id="case-13"></a>

### 13 主动中止后保存已完成的工具结果

- **类型** 服务集成测试。
- **目的** 验证落盘没有破坏现有中止规则。
- **怎么测** 在会话 A 并行工具运行时中止，让已启动工具按实际结果收尾。检查已完成结果正确保存，旧任务显示已中止，后续模型请求次数为零。

<a id="case-14"></a>

### 14 工具结果未保存的卡片不可展开

- **类型** 组件测试（Chromium）。
- **目的** 验证只展示已确认的保存失败状态。
- **怎么测** 向页面交付 B 已执行但结果未保存的会话快照。检查 B 的状态为 Error，只显示「工具已执行，结果未保存」，没有展开入口。任务末尾显示实际保存失败原因。

## 压缩、回看与接续

<a id="case-15"></a>

### 15 摘要写入失败时继续保留上一次有效上下文

- **类型** 会话集成测试。
- **目的** 确保摘要在保存成功前不会生效。
- **怎么测** 准备已有成功压缩的会话，再触发一次手动压缩，生成有效摘要后让保存失败。检查原始消息和上一次成功摘要保留，本次记录未被当作成功。

<a id="case-16"></a>

### 16 刷新网页后仍能看见同进程的保存失败

- **类型** 服务集成测试。
- **目的** 验证内存里的失败信息能被重新取得。
- **怎么测** 在 B 的工具结果写入失败后，断开当前会话订阅，在同一个本地服务上重新打开该会话。检查初始快照仍携带 B 的保存失败和本轮失败状态，且没有重跑旧任务。

<a id="case-17"></a>

### 17 重启后两段会话各自恢复完整历史

- **类型** 服务集成测试。
- **目的** 验证原编号、工作区及记录的隔离。
- **怎么测** 准备 A、B 两段具有不同消息和工具结果的会话，让 A 有已保存压缩记录。重启服务，从列表分别打开 A 和 B。检查编号、原文、工具调用与结果顺序、压缩记录均各归其主，打开时模型和工具调用次数为零。

<a id="case-18"></a>

### 18 进程中断后保留 A 的结果并显示 B 结果未知

- **类型** 服务集成测试（独立服务进程）。
- **目的** 验证恢复时按磁盘证据显示中断。
- **怎么测** 让 A 的结果落盘，让 B 的调用落盘。B 写入结果前强制结束服务进程。重启后打开原会话，核对 A 结果存在、B 结果未知、旧任务已中断。

<a id="case-19"></a>

### 19 用户主动续聊时模型收到结果未知的说明

- **类型** 服务集成测试。
- **目的** 验证恢复说明真正进入新的模型输入。
- **怎么测** 从上一轮中断的数据库打开原会话。用户发送「继续」，捕获实际模型请求。核对模型收到已保存的有效上下文和 B 的结果缺失说明，并被提醒修改 README.md 前先检查现状。确认缺失说明未被写成真实工具结果。

<a id="case-20"></a>

### 20 工作区目录暂时不可用时仍可回看

- **类型** 服务集成测试。
- **目的** 验证回看与执行目录校验各自独立。
- **怎么测** 保存一段会话后移动测试工作区目录。重启并打开该会话，检查历史可读。尝试继续发送，检查明确提示目录不可用，模型调用次数为零。

<a id="case-21"></a>

### 21 真实网页会话两次压缩后重启并继续任务

- **类型** 端到端测试（Chromium、真实 DeepSeek）。
- **目的** 证明真实模型、工具、页面和 SQLite 在重启前后能接续。
- **怎么测** 在网页为 A 做至少两轮真实工具调用和两次压缩，为 B 留下不同的记录。重启服务，分别核对原文、工具结果和 A 的两次压缩及 token 依据。由用户在 A 主动发起一条依赖旧对话的消息，核对实际模型请求使用 A 的摘要和近期原文，实际结果与 A 的任务一致。此例需要真实模型、浏览器和服务协作。

<a id="case-22"></a>

### 22 正常对话完成后重启仍能在原会话看到消息

- **类型** 端到端测试（Chromium、受控模型）。通过网页侧栏和消息列表验证实际回看结果。
- **目的** 验证正常写入的用户消息和模型回复能在服务重启后从原会话找回。
- **怎么测** 用临时 SQLite 库启动服务，从网页新建会话并发送「记住代号青禾」。让测试模型回复「已记住青禾」，等待本轮完成并记录会话编号。正常关闭服务，再用同一份库启动新服务。重新载入网页，从侧栏打开原会话，检查会话编号一致、两条消息的原文和顺序正确，本轮仍是完成状态，打开会话时没有发起模型请求。

<a id="case-23"></a>

### 23 重启后主动发送时沿用原会话上下文

- **类型** 服务集成测试（独立服务进程、受控模型）。
- **目的** 验证重启后由用户主动发起的新一轮会把原会话的历史交给模型。
- **怎么测** 通过实际发送入口正常完成「记住代号青禾」和「已记住青禾」这一轮，再用同一份 SQLite 库重启服务。打开原会话后，用户主动发送「刚才的代号是什么？」捕获服务发给测试模型的实际请求，核对它按顺序携带上一轮用户消息、上一轮模型回复和这次新消息。让模型回复「代号是青禾」，核对本轮新消息和回答均已保存到原会话。

## 数据库接管与读取

<a id="case-24"></a>

### 24 第二个服务启动时报告会话库已占用

- **类型** 服务集成测试（两个独立进程）。
- **目的** 验证独占保护不依赖监听端口。
- **怎么测** 第一个服务用会话库运行任务时，用不同端口启动第二个服务并指向同一份库。检查第二个服务明确报告已占用，第一个服务的任务仍正常运行，原任务状态不被改写。

<a id="case-25"></a>

### 25 正常关闭后新服务可以接管

- **类型** 服务集成测试（独立服务进程）。
- **目的** 验证服务收尾后释放接管权。
- **怎么测** 让第一个服务写入会话后正常关闭。以原库启动新服务，检查能够接管并恢复原编号的会话。

<a id="case-26"></a>

### 26 进程异常退出后新服务可以接管

- **类型** 服务集成测试（独立服务进程）。
- **目的** 验证接管不依赖上次正常关闭。
- **怎么测** 第一个服务持有库时强制结束该进程。以原库启动新服务，检查能够接管，读取此前已提交的记录。

<a id="case-27"></a>

### 27 首次打开的历史来自同一个已提交版本

- **类型** 存储集成测试。
- **目的** 验证四张表的数据以同一时点读取。
- **怎么测** 在历史读取期间安排一次更新尝试，更新同时改变消息、任务或其压缩关联。检查返回的是更新前或更新后的完整状态，引用的消息都属于同一次读取。

<a id="case-28"></a>

### 28 历史读取失败时页面不进入可发送状态

- **类型** 服务与页面集成测试。
- **目的** 验证读取失败有明确反馈。
- **怎么测** 会话摘要可读，令指定会话的消息或压缩记录读取失败。检查打开返回明确错误，没有交付半份快照，发送不可用。恢复读取后重新打开，检查完整记录可见。
