# Feature8 实施计划

设计与范围见[技术设计](./feature8-基础Session机制技术设计.md)，验证按[验收标准](./feature8-验收标准.md)执行。

- [x] 执行与会话分层。先覆盖通用工具详情、超限返回，再迁移现有压缩与模型循环。`AgentSession` 保持整个任务的编号、取消信号与快照。`Sessions` 管工作区归属、编号、列表和关闭。
- [x] 工作区与服务协议。验证旧登记兼容、真实路径去重和目录失效；通过 HTTP 创建和查询会话，按会话编号提交和中止，WebSocket 按会话和订阅编号发快照与增量。增加并发、未知目标和关闭收尾测试。
- [x] 网页会话、草稿和回执。用通信和组件测试验证旧帧、迟到回执和存储故障；切换会话时恢复原文、按当前会话显示状态，继续沿用现有的提交及中止规则。
- [x] 工具及运行入口。迁移八种工具和回归测试，保留网页服务商装配与本机授权。更新工作区构建、开发监听、测试入口和文档。
- [x] 验收。运行完整构建、根测试、真实工具套件、Git 差异检查。使用实际页面验证并行、刷新、重新开页和断线恢复；使用真实模型验证会话接续、工具结果归属和压缩隔离。将每项结果和环境限制记入验收记录。

复跑结果及证据见[最终复跑](./feature8-验收标准.md#results)。

## 单一新会话草稿

- [x] 后端接收首条消息时才登记正式会话。同一个首发编号可安全重试，拒绝时不登记空会话。
- [x] 顶部入口和工作区入口共用一份草稿。目录可切换、可用系统面板添加，记住上次选择。首发成功后切到正式会话，等待期间保留草稿和用户新的导航选择。
- [x] 用 Chromium 和受控模型验证实际目录、草稿、首发、迟到回执与空会话数。复跑后端、组件、实际入口和真实服务商回归。

结果见[新会话首发复跑](./feature8-验收标准.md#first-send-results)。
