# 在 SI 使用 Skill

Skill 是一份可以重复使用的工作方法。写好用途后，Agent 遇到匹配的任务会按需读取说明。你也可以在输入框键入 `/`，从「技能」选择一项，输入框会填入蓝色的 `/skill:名称`，可以继续补充要求再发送。也可以直接输入 `/skill:名称`。

## 查找范围

SI 按以下顺序从磁盘读取，同名采用最先发现的有效版本。

1. 当前工作区的 `.si/skills/`。
2. 从工作区逐级向上找 `.agents/skills/`，包含最近的 Git 根目录。无 Git 根时查到文件系统根。
3. 个人 `~/.si/skills/`，随后是 `~/.agents/skills/`。
4. SI 应用的 `resources/skills/`，随应用提供。

各目录递归查找 `SKILL.md`。一个目录已有这份说明时，目录内其余文件作为该 Skill 的资料。SI 兼容 `.si/skills/` 下直属的 `.md` 与 `.agents/skills/` 下子目录里的 `.md`。在菜单打开或下一条任务被接收时重新发现。运行中的任务沿用已有目录，历史显式调用保留当时加载的正文。

## 文件格式

使用 UTF-8 的普通 Markdown 文件，大小最多 256 KiB。文件以 YAML 文件头开始。名称最多 64 个字符，使用小写字母、数字和分隔单词的单个连字符。描述为 1 至 1024 字符。也可设 `disable-model-invocation: true`，只接受用户指定，菜单仍可选。

```markdown
---
name: review-changes
description: 复核项目改动，并给出每个问题的文件位置和证据。
---

先查看改动及相应测试，再列出可核对的问题。每项写明路径与触发条件。
```

细节和脚本可放在同目录的 `references/` 与 `scripts/`。说明里以相对路径引用这些文件，从说明文件所在目录起算。用 read 读取说明和相关资料。运行脚本和写入都受会话权限约束。只读模式可检查文件和分析方法。可自动调用的用途和文件位置随系统提示发给当前模型服务商，正文随实际读取或显式调用进入对话。

## 创建和修改

- 项目 Skill 保存到当前工作区的 `.si/skills/<名称>/SKILL.md`。当前工作区的绝对路径以系统提示词的 `<cwd>` 为准，工作区是子目录时也基于该路径保存。个人 Skill 保存到 `~/.si/skills/<名称>/SKILL.md`，个人目录的绝对路径见系统提示词。
- 分开确认 Skill 的**用途**和**保存位置**。例如，「用于核对本工作区的交付」说明它处理哪里的文件。用户说「保存为项目 Skill」或给出具体路径，才确定保存位置。未选范围且未给出路径时，先在聊天中询问项目或个人，等用户答复后再写任何文件。
- 新建前检查目标文件与各发现位置的同名项，包括仅限用户调用的项。没有指定路径且已有同名项时，先给出来源和路径，并让用户在修改已有项与换名新建之间选择。在用户决定前保留文件原样。
- 修改已有 Skill 时，按用户给出的路径或查找优先级定位文件。用 read 查清原文，再用 edit 精确修改。使用 write 创建新文件。
- 修改预置 Skill 时，在用户选择的项目或个人范围内保存同名副本，保留配套文件与许可证。检查目标是否存在，并按上面的同名规则处理。应用预置版本作为后续副本的来源保留。
- 用 read 核对实际写入的每个文件。写入或读回失败时，列明已确认的结果和仍要检查的文件。用下一条相关任务验证 Skill 能被发现，且任务确实按步骤产生了可检查的结果。
