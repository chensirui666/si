# 在 SI 创建和使用子 Agent 角色

子 Agent 角色是一份可重复使用的 Markdown。文件描述它擅长什么、怎么做事以及可选的工具和模型。创建角色后，可以在聊天里告诉主 Agent「用 `test-reviewer` 检查这次改动缺哪些测试」。主 Agent 会按角色启动独立子会话并交办这次任务。

## 保存位置

- 个人角色保存到 `~/.si/agents/<名称>.md`，可在不同工作区使用。
- 项目角色保存到登记工作区的 `.si/agents/<名称>.md`，作用域为该工作区。

项目角色默认关闭。要启用时，在 `~/.agent-learning/workspaces.json` 中找到对应的工作区记录，添加 `"projectAgentsEnabled": true`，保留原 ID、路径和已有字段。改成 `false` 后，SI 会拒绝新建或续用该工作区的项目角色任务。

主 Agent 默认查找个人和已启用的项目角色，出现同名时优先采用项目版本。需要指定个人版本时，可以在聊天里说「用个人角色 `test-reviewer`」。子任务可以在另一个目录运行，角色仍从原工作区查找。项目角色目录和文件链接到指定位置以外时会被跳过。

## 文件格式

使用 UTF-8 Markdown。文件顶部的 YAML 头必填 `name` 和 `description`。`name` 是主 Agent 调用时使用的角色名，同一个目录里的角色应各用一个名字。`description` 用一句话写清角色适合处理的任务，主模型会用它来选角色。Markdown 正文是启动该角色时使用的长期工作指令。

- `tools` 可选。列出角色可使用的常规工具，实际可用范围还受会话权限约束。省略时沿用会话可用范围，填 `[]` 时只保留子 Agent 的团队协作工具。
- `model` 可选。填 SI 已配置的模型标识，省略时沿用主会话的模型和推理级别。

下面的例子可以保存为 `test-reviewer.md`。

```markdown
---
name: test-reviewer
description: 检查代码改动遗漏了哪些测试场景
tools: [read, grep, find, ls]
---

阅读相关实现和现有测试。列出缺失的测试场景、涉及的文件，以及判断依据。
```

## 让 SI 创建或修改角色

1. 先读取本指南，根据用户想交给角色的工作确定名称、用途、指令和保存范围。可以把期望的输出写进正文，例如每个发现都附上文件位置和理由。
2. 检查目标位置。新建时用 `write` 创建角色 Markdown。修改已有角色时先用 `read` 查看原文，再精确更新。按用户指定的范围保存。用户也要求启用项目角色时，再更新对应工作区的配置。
3. 保存后读回文件，核对角色名称、配置和指令，并向用户说明保存路径与可用范围。主 Agent 下一次请求模型时会重读角色目录。实际启动角色时，SI 会读取最新的文件和授权设置。

如果只是希望临时把这次任务交给一个子 Agent，可以让主 Agent 直接委派，由 SI 提供通用子 Agent 指令。
