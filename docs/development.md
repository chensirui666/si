## 运行项目

已接入本机授权、DeepSeek 流式聊天和八种工具。先配置模型，再点侧栏顶部「新会话」，或点工作区旁的新建按钮。两个入口共用一份草稿。顶部入口记住上次选过的目录，工作区入口预选该目录。输入框上方可切换目录，或通过「添加工作区…」打开 macOS 文件夹选择面板。首条消息和会话登记写入成功后，正式会话才会出现在最终选中的工作区下。

切换会话时，已经开始的任务继续运行，可以切回查看进度或中止。刷新、重连或重新打开网页可找回会话。同一浏览器按会话保存草稿。服务重启后，可在原工作区回看已保存的聊天、工具结果和压缩记录，再主动发送一条消息继续。重启前缺少结束记录的任务显示「已中断」。只有调用记录的工具显示「结果未知」，继续时 Agent 会收到先检查文件等外部状态的提醒。

```sh
npm ci
npm run build
npm --prefix packages/server start
```

打开终端打印的完整授权链接，浏览器取得 Cookie 后自动跳转到干净地址。默认监听 `127.0.0.1:3000`；首次启动会安全创建 `~/.agent-learning/browser-auth.json`。不要分享授权链接。签名文件损坏或权限错误时服务拒绝启动，不会自动覆盖它。会话默认保存在 `~/.agent-learning/sessions.sqlite`，同一个会话库由一个本地服务接管。若启动时提示库被占用，先关闭正在使用这份库的服务。

从侧栏底部“设置 → 模型 → 添加提供方 → DeepSeek”保存 API Key，可替换或删除。Key 仅写入本机 `~/.agent-learning/auth.json`，页面只接收配置状态；多个页面会同步模型列表，重启后配置仍在。保存成功只表示本地配置可用，不表示远端认证通过。模型文件损坏仍可进入设置，但需要先人工修复文件，页面不会覆盖坏文件。

新会话的首条消息被接收后清空本次草稿。已开始的会话发起发送后立即清空本次草稿。提交被明确拒绝时，如果原会话还没有新草稿，原稿会恢复到那段会话。提交未确认时，只有该会话需要继续等待。生成或连接恢复期间可编辑草稿，等任务结束或连接恢复后再发送。

发送后主按钮切换为「中止」，收到后台运行状态后启用。点击后等待本次模型或工具收尾，保留已有内容和结果，确认空闲后可继续发送。中止期间仍可编辑草稿，保留撤销记录。停止不会撤销已经发生的文件修改；刷新、关闭页面或断线不自动停止任务。具体校验见 [Feature5 验收记录](里程碑1/feature5/feature5-验收记录.md)。

一次提交可以连续完成多轮操作：Agent 等模型给完本轮工具调用，再执行并回填真实结果，让模型决定继续操作还是回答。例如先读 index.txt，根据线索再读 note.txt，最后回答项目名称，无须拆成两次提交。每轮仍可使用全部八种工具。同批默认并行；任一工具声明需要串行时，整批按顺序执行。并行不会自动检查文件依赖，同批或不同会话同时修改同一文件时，改动可能相互覆盖，有依赖的操作应分轮完成。

运行时「执行过程」持续显示各轮思考与工具状态，整次任务结束后自动收起，仍可展开查看参数和真实结果。工具调用先保存再执行。串行工具逐项保存结果，完成一批并行工具后按调用顺序逐条保存并显示结果。带工具调用的回复被截断时，本批全部不执行，回填未执行原因后允许模型重新决策；纯文字截断则保留文字、提示不完整并结束。中止等全部已启动操作收尾，不改写先前的成功或失败，也不撤销文件修改。暂不设整任务轮数上限，接近容量时会自动压缩，反复调用可能增加费用，可随时中止。见 [Feature6 验收记录](里程碑1/feature6/feature6-验收记录.md)。

发送任务时，Agent 自动读取全局配置目录 `~/.agent-learning/`、工作区及其上层目录里的项目说明，例如 `AGENTS.md`。每轮模型请求前都会重新检查，任务中的工具改完说明后，下一轮即可使用新版。说明全文与来源会随普通任务发送给模型。若说明文件是符号链接，服务会读取链接指向的普通文件，即使它位于工作区外。具体规则见 [Feature9 技术设计](../planning/里程碑1/feature9/feature9-项目说明加载与启动上下文技术设计.md)。

在空闲时输入 `/`，从命令菜单选择 `/compact` 后再发送，可主动压缩较早对话；接近模型容量时也会自动压缩。后续请求使用“摘要＋近期原文”，原始聊天与工具记录仍可查看。失败、中止或摘要未缩短时保留原有效上下文；明确超限只压缩恢复当前请求一次，不重跑已完成工具。项目说明与聊天历史分别准备，压缩只整理聊天历史。

压缩摘要会附上已整理历史中的仅读文件与已改文件，可在「查看摘要」里查看。清单来自 `read`、`write`、`edit` 确认发生的操作，同一路径改过就只列在「已改文件」。写入完成后收到中止，仍会保留已改记录。

发送按钮左侧的容量圆环可悬停或键盘聚焦查看系统提示词、工具定义、对话消息的近似分布。压缩记录分别显示前后估算、摘要调用消耗与后续真实请求输入；估算不是精确计费数据。摘要可能遗漏信息，长工具结果只取前 1,500 和后 500 个完整字符用于整理，原始记录不截取。刷新、重连或服务重启可回看已保存的聊天与摘要。见 [Feature7 验收记录](里程碑1/feature7/feature7-验收记录.md)。

本地工具有 `read`、`bash`、`edit`、`write`、`find` 和 `grep`。工作区是相对路径的起点，工具拥有本机服务进程的文件和命令权限。网页工具 `web_search` 与 `web_fetch` 通过「设置 → 网页工具」配置，默认共用 Tavily Key。使用网页工具前，在该设置页保存 Tavily Key。服务商选择写入 `~/.agent-learning/settings.json`，Key 写入同目录下的 `auth.json`。

开发时分别运行：

```sh
npm run dev:server
npm --prefix web run dev
```

前者首次构建全部后端包，并监听 Credentials、Model、Agent、Coding Agent、Server 的源码变化和重启；后者固定使用 `127.0.0.1:5173`。打开后端打印的“开发入口”链接（`/auth?token=…`），由 Vite 同源代理交换授权并连接。`AGENT_LEARNING_SERVER_PORT` 可为后端和 Vite 指定一致的其他端口，Vite 页面端口仍固定 5173。

## 校验

```sh
npx playwright install chromium
npm test
```

根 `npm test` 先构建后端并跑 Credentials、Model、Agent、Coding Agent、Server 测试，再运行网页单元测试、真实 Chromium 组件测试、两种实际入口 E2E。E2E 前会执行完整构建；测试只使用临时签名与模型文件，不访问真实用户配置。

真实服务商验收需显式提供已有 dotenv 文件位置，文件包含 `DEEPSEEK` 或 `DEEPSEEK_API_KEY`。Key 只读入内存，再经真实设置页面保存到测试临时目录；不改原文件、不输出 Key、不保存包含凭据的浏览器 trace。未提供时该项明确跳过，不能据此声称通过真实模型验收。

```sh
DEEPSEEK_LIVE_KEY_FILE=/absolute/path/to/test.env npm test
```

多会话验收见 [Feature8 验收标准](../planning/里程碑1/feature8/feature8-验收标准.md)。项目说明验收见 [Feature9 验收标准](../planning/里程碑1/feature9/feature9-验收标准.md)。本地存储与重启恢复见 [Feature10 验收标准](../planning/里程碑1/feature10/feature10-验收标准.md)。

独立命令、系统输入法检查和说明见 [web/README.md](../web/README.md)。Feature2 的实际证据见 [Feature2 验收记录](里程碑1/feature2/feature2-验收记录.md)。

八种工具都从正式服务入口验收。根测试在 Chromium 中发起真实 `read`，其余七种通过下面的命令调用实际 HTTP 和 WebSocket 接口。每项核对工具执行、结果回填及最终回答。指定包含 `DEEPSEEK` 或 `DEEPSEEK_API_KEY` 的 dotenv 文件，以及包含 `TAVILY_API_KEY`（也接受 `TAVILY` 或 `tavily`）的测试文件，两者可以使用同一个文件。凭据和工作区使用测试临时目录。

```sh
npm run build:packages
DEEPSEEK_LIVE_KEY_FILE=/absolute/path/to/test.env \
TAVILY_LIVE_KEY_FILE=/absolute/path/to/test.env \
npm --prefix packages/server run test:tools:live
```

实际结果见 [Feature4 验收记录](里程碑1/feature4/feature4-验收记录.md)。
