# 创建或修改 Skill

1. 用 read 完整阅读系统提示词给出的 SI 应用 `docs/skills.md`，以它的路径和规则为准。读不到时说明原因，等规则可用再动手。
2. 从用户给出的实际任务提炼触发条件和可核对的结果。再看用户是否明确说了保存为项目 Skill、个人 Skill 或具体路径。「核对本工作区」描述的是用途。缺少保存选择时，只问用户选项目还是个人，等下一条回复再写文件。
3. 项目范围以系统提示词的 `<cwd>` 为准，即使它位于 Git 仓库的子目录。按规则检查同名项和目标文件。新建遇到同名且用户没有指定路径时，先给出现有来源与路径，再询问修改或换名，等用户决定。
4. 把必做步骤放在 SKILL.md，详细资料按需放到配套文件。修改前先读原文。涉及预置版本时将配套文件及许可证一起复制到用户选定的位置。
5. 写入后逐个读回已改文件。报告实际核对过的路径，并给出一个能验证步骤和结果的后续任务。
